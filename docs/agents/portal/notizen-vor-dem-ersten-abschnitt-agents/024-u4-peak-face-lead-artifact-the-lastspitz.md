# U4 Peak face lead artifact + the Lastspitzen subpage (design data/vp-ems-ui-overhaul/report.md §6 Face 2, epic UO #515

Ausgelagert aus `frontend/portal/AGENTS.md` am 05.09.2026 (Abschnitt Nr. 1, Punkt 024).

- **U4 Peak face lead artifact + the `Lastspitzen` subpage (design `data/vp-ems-ui-overhaul/report.md` §6 Face 2, epic UO #515, builds on U1–U3).** The cockpit is still the SAME component tree; U4 adds ONE new mechanism — the **lead-slot switch** — plus a dedicated subpage.
  - **The lead-slot switch is the pure, unit-tested `src/leadSlot.ts` `leadArtifact(emphasisPeak): 'peakband' | 'money'`** (the `moneyEmphasis`/AE7 pattern): a peak-profile site (AE7 `emphasis.peak === 'prominent'`) leads its cockpit with the **Peak-Band**; everything else — private/arbitrage, un-migrated, profile-less, null/unknown — leads with money, byte-identical to today (`leadSlot.test.ts`). `AnlagenPage` `AnlageSeite` derives `emphasis` once (`adaptiveLive.adaptive ? profile.emphasis : null`), passes `emphasis?.money` to the unchanged `moneyLayout` and `emphasis?.peak` to `leadArtifact`; the Peak-Band renders ABOVE the money zone, money stays below as **Nachweis** (AE4 already frames peak money `secondary` — no change there).
  - **The Peak-Band (`src/peakBand.ts` + `components/PeakBand.tsx`, AE0 mockup `.peak`):** current ¼-h grid-import mean vs. **Ziel** (progress bar + red limit marker) + **vermiedene Spitze** + **ersparte Leistungskosten**. Pure `peakBand({current, targetKw, peak})` builds the bar geometry (`BAR_HEADROOM 1.2`, breach when current > Ziel) + the PS-4 metrics (from `earnings.peakShaving.avoidedKw/avoidedEur`, `AVOIDED_NOISE_KW` deadband) + honest notes. The **live ¼-h mean** is `quarterHourMeanImportKw(samples, now)` — import-only (`max(power_kw,0)`) over the RUNNING wall-clock quarter (epoch-ms floor aligns with Europe/Berlin since offsets are whole-hour), null (never 0) when no usable sample, `fresh` = newest sample within 5 min. The edge PS-3 tracker is edge-only; deriving in the portal from a 20-min telemetry window is the honest cloud twin. `AnlageSeite` fetches that window ONLY when the cockpit leads with the Peak-Band (gated effect, LIVE cadence), so non-peak faces never pay for it. Tests: `peakBand.test.ts` (mean + view exhaustively), `PeakBand.test.tsx` (thin render).
  - **The `Lastspitzen` subpage (`#/anlage/{id}/lastspitzen`, `pages/LastspitzenSection.tsx`, `nav.ts` sub `lastspitzen`):** (1) PS-4 proof KPIs (running billing period), (2) per-period **history chart** `components/PeakHistoryChart.tsx` over `earnings.peakShaving.history` (baseline vs. gehaltene Spitze bars, gap = avoided; was noted not-yet-rendered), (3) the **Fahrplan with the peak-target overlay** — `ScheduleChart` gained an optional `peakTargetKw` prop that draws a red dashed **Ziel Netzbezug** markLine on the power axis and grows the axis max to keep it visible. A site with no active peak module → honest EmptyState (deep-link safe). (The former `adaptiveNav.ts` peak-face promotion is gone; since Portal v3 M1 `Lastspitzen` is a real sidebar entry inside the `Modus · Lastspitzenkappung` group.)
  - **The Ziel comes from `schedule.peakTargetKw` (customer-reachable), NOT `optimizer-config` (admin-only).** Backend: `SchedulePlanDto`/`ScheduleRepository` expose the existing `schedule.peak_target_kw` column additively on the SAME `GET /api/v1/sites/{id}/schedule` endpoint (no new endpoint); `api.ts` `SchedulePlan.peakTargetKw`; `openapi.yaml` + `PortalApiTest.scheduleEndpointReturnsLatestPlanTenantScoped` cover it. Null = no peak module / pre-column run → no target line (never a fabricated 0).
