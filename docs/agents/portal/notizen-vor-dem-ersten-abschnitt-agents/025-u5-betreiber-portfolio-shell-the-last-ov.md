# U5 Betreiber PORTFOLIO shell — the LAST overhaul phase (design data/vp-ems-ui-overhaul/report.md §6 Face 4 + §5.3 + §2.3

Ausgelagert aus `frontend/portal/AGENTS.md` am 05.09.2026 (Abschnitt Nr. 1, Punkt 025).

- **U5 Betreiber PORTFOLIO shell — the LAST overhaul phase (design `data/vp-ems-ui-overhaul/report.md` §6 Face 4 + §5.3 + §2.3, epic UO #516, builds on U0/U1).** A betreiber tenant lands on a real Portfolio page instead of U0's interim fleet Übersicht (that `// TODO(U5,#516)` marker is gone). `pages/PortfolioPage.tsx` = an aggregate KPI row (`KpiCard`s: Σ Speicher kWh·kW, Ø Ladestand, Erlös heute, Erlös Monat, Σ vermiedene Spitze — the last shown only when a module-active site exists) over an operator **`.vp-table.responsive`** table (Anlage · Profil-Chip · Entitäten · Ladestand · PV jetzt · Erlös heute · Status; collapses to label/value cards <720px). Each row drills into that Standort's OWN cockpit via `onNavigate(anlageRoute(s.id))` — **Portfolio is the Betreiber SHELL, not an AE7 profile; it reuses the SAME AnlagenPage cockpit the Endkunde shell renders (one cockpit, two shells).**
  - **ALL derivation is the pure, unit-tested `src/portfolio.ts` (`portfolio.test.ts`):** `roleBadges(roleCounts)` (Σ per role, non-zero only, canonical pv·storage·consumer·grid order, **design-system `Icon` names — sun/battery/zap/activity — NEVER emoji glyphs** despite the design's "🔋2 ☀️3" shorthand, per the portal icon convention), `profileChip(usageProfile)` (arbitrage→Arbitrage / peak→Lastspitze / private→Privat / unknown→Standard), `siteStatus`/`siteSoc`/`siteNowKw` (fresh-PV only, `siteLiveFresh` from fleet.ts)/`siteSavedToday`, and `portfolioKpis(overview, earnings, now)` — Σ storage from `overview.totals`, Ø SoC as the plain average of plausible live readings, Erlös heute (summed `dailySaved`) + Monat (`earnings.totals.savedEur`), Σ avoided-peak from the per-site `peakShaving` blocks (PS-4). Everything nulls (never fake zeros) when nothing is computable; a null/absent roleCounts/usageProfile (older backend) is handled safely.
  - **The shell decision lives in `src/betriebsart.ts`:** `isBetreiberShell(b)` / `showPortfolioNav(i)` and the ONE canonical redirect function `canonicalShellRoute({shell, route, siteIds})`. It runs only after the site list and tenant context are ready and returns the FINAL route, so `App.tsx` performs at most one `history.replaceState` instead of the former loop `Übersicht → Anlagen → Portfolio → Übersicht`. Betreiber land once on Portfolio; an endkunde with exactly one Anlage sends Übersicht, the naked Anlagen route and every forbidden Portfolio route directly to that Anlage; valid deep links stay untouched, and an invalid site id is corrected while preserving its deep sub/device target. `canonicalShellHash` carries the current query suffix byte-for-byte because `Route` intentionally has no query. Admins follow the selected tenant's real shell level: fleet contexts canonicalize to Portfolio, non-fleet Portfolio bookmarks to Übersicht (pinned for `endkunde`/`betreiber`/`null` × 0/1/2 sites). `routeCanonical.test.ts` pins landing, idempotence, deep-link/query stability, the admin matrix and hydration gating.
  - **Backend: ONE additive `/overview` rollup** — per-site `roleCounts` (Σ v2 entities per role via the `EntityTypeCatalog` category→role map: storage→storage, producer→pv, meter→grid, consumer→consumer; one entity counts once) + `usageProfile` (the SAME `UsageProfileDeriver` the profile endpoint runs, fed the entity mix + active-flow strategy nodes + money master data), plus fleet Σ `storageCapacityKwh`/`storagePowerKw` on `totals` (from the v1 `asset` rows — no new schema). RLS-scoped exactly like the rest of `/overview`. `OverviewController`/`OverviewRepository`/`OverviewDto` + `openapi.yaml`; proven by `PortalApiTest.overviewCarriesPerSiteRoleCountsUsageProfileAndStorageTotals`.
  - CSS block "Betreiber PORTFOLIO shell (U5)" in `index.css` (`.vp-portfolio-kpis` auto-fit grid, `.vp-entity-badges`/`.vp-entity-badge`, `.vp-profile-chip` + per-face tints, `.vp-portfolio-warn`) — reuses the proven `.vp-table.responsive` collapse so the page never overflows horizontally at phone width.
