# M3 Cockpit als Modul-Stapel — the Übersicht IS the projection (Epic "Projektion" #527, ticket #531; design data/vp-anlag

Ausgelagert aus `frontend/portal/AGENTS.md` am 05.09.2026 (Abschnitt Nr. 1, Punkt 027).

- **M3 Cockpit als Modul-Stapel — the Übersicht IS the projection (Epic "Projektion" #527, ticket #531; design `data/vp-anlagen-face-k9/report.md` §1.3/§2.2/§3/§6 + `feedback.md`).** `AnlageSeite` (`pages/AnlagenPage.tsx`) now has **two render paths**: a migrated Anlage renders the deterministic **module stack**; everything else renders the untouched v4 zone dashboard. The switch is the pure `cockpit.ts` `projectionActive({hasEntities, adaptive})` — **BOTH gates must be open** (M0 `surface.base.hasEntities` AND the existing `useAdaptiveLive`/`hasTopology` law); null/undefined (older backend, load failure) falls back to v1.
  - **All derivation is the pure, unit-tested `src/cockpit.ts` (`cockpit.test.ts`):** `cockpitStack(blocks, leadId)` (the M0 blocks in their canonical §1.3 rank, each with its visible **„von"-Tag** — the contributing mode, or `Entitäten` for base — and its **drill-ins**; `status` is rendered by the page head and `toolbox-pointer` is the closing line, so both are filtered out), `handelBlock(...)` and `eigenverbrauchBlock(...)` (the two NEW blocks, built from EXISTING data only — `savedEur`/`arbitrageEur` + the persisted plan's charge/discharge windows with energy-weighted Ø price; Autarkie/PV-Nutzung from the Historie day totals + `coverUntil` from the plan), `automationRows`, `planWindows`/`dominantWindow`/`windowHours`. **No new engine, no fabricated number:** a tile without a source is omitted, never rendered as 0.
  - **The lead rule is N-ary now (`leadSlot.ts` `leadBlock`): peak → money → flow**, derived from the ORDERED block list (`LEAD_CANDIDATES`), so the lead can never disagree with the stack below it. The binary U4 `leadArtifact(emphasis.peak)` stays — it is the **v1 path's** rule. A "Neu / leer" Anlage has no lead (its cockpit is M5's setup path).
  - **Drill-ins replace the retired tab bar (§2.2):** Live + **Verlauf** ← the Energiefluss block (base), Erlöse ← the Erlös-Komposition (M4 renders its own header/drill-in — M3 only PLACES it), Fahrplan ← Handel/EV, Lastspitzen ← Peak-Band, Steuerung ← Geräte-Automatik. **The Telemetrie-Historie is a BASE drill-in in EVERY mode** and is deliberately NOT the Erlös-Historie: there is no separate telemetry-history route, so „Verlauf" points at `#/anlage/{id}/live` (where the `TelemetryChart` lives) while „Erlöse im Detail" points at `#/anlage/{id}/historie`. That keeps `nav.ts`/the M1 shell untouched; the v3 M1 shell mounts every deep view as a real sidebar/Mehr-sheet entry, so nothing depends on a page-head menu.
  - **Ausprägungen hold structurally (§3):** a private Anlage renders hub + EV + Automatik and NO peak/market block; a park renders Handel and NO „Haus"/Eigenverbrauchs-Block. Category errors are impossible because a block only exists when its mode does — pinned per Ausprägung in `cockpit.test.ts`.
  - **The v1 invariant is proven, not asserted** (`pages/AnlagenPage.test.tsx`): the same un-migrated Anlage is rendered with a NULL surface (older backend) and with the empty projection, and both DOMs must be **character-identical** — plus no `.vp-stack`/`.vp-block`/`.vp-toolbox-line` node may exist. Component CSS is the component-local `components/CockpitBlocks.css` (the M4 precedent), so `index.css` stays untouched.
