# Customer flow surface (E3b, Anlage → Steuerung).

Ausgelagert aus `frontend/portal/AGENTS.md` am 05.09.2026 (Abschnitt Nr. 1, Punkt 045).

- **Customer flow surface (E3b, Anlage → Steuerung).** The customer half of the flow editor: `#/anlage/{id}/steuerung` (`nav.ts` sub `steuerung`, `pages/SteuerungSection.tsx`, DetailCard on the Anlagen-Seite) - a Portal-User builds/validates/simulates/activates the flows of their OWN Anlage. It **REUSES the exact `FlowEditorPage`** (palette/canvas/inspector) - not a fork: the editor now takes a site-bound `BoundFlowApi` (`src/flows/flowsApi.ts` `adminFlowApi(tenantId,siteId)` / `customerFlowApi(siteId)` factories, identical response shapes) instead of `tenantId`, plus `canEnableGated`/`lockedHint`. The **palette is governance-aware** (`api.governance()` → enabled gated types): a gated strategy node is placeable for admins and for customers only once VoltPilot enabled it, else it renders **locked** with `EINRICHTUNG_DURCH_VOLTPILOT` (the old hardcoded Peak/atyp-NN locked pair was removed). The customer surface never weakens a gate (the backend re-checks; the customer cannot enable). **Customer control templates** are the pure `src/flows/customerTemplates.ts` (unit-tested `customerTemplates.test.ts`): each `resolve`s against `api.siteEntities` (mapped to `EditorEntity`) + is `applyDerivedClaims`-stamped so it validates clean; "Wallbox nur bei PV-Überschuss" + "Heizstab-Zeitplan" are FREE-node flows, the Marktoptimierung pilot is gated (shown with its Freischaltung state). The editor also gained a "Stilllegen" action (`api.deactivate`) when a flow is active. Backend: root AGENTS.md "Customer flow release (E3b)".
