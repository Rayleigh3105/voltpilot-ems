# /assets/ fällt NIE auf index.html zurück — ein verschwundenes Bundle ist ein hartes 404 (location /assets/ + @assets_mis

Ausgelagert aus `frontend/portal/AGENTS.md` am 05.09.2026 (Abschnitt Nr. 1, Punkt 041).

- **`/assets/*` fällt NIE auf `index.html` zurück — ein verschwundenes Bundle ist ein hartes 404 (`location /assets/` + `@assets_missing` in `nginx.conf`; Live-Befund Scout vp-stale-view-w2, 04.08.2026).** Nach jedem Deploy sind die alten gehashten Bundles aus dem Image verschwunden; der SPA-Fallback beantwortete sie mit 200 + `index.html` als `text/html` — und Cloudflare cachte dieses HTML unter der `.js`-URL am Edge und stempelte seine Default-Browser-TTL (`max-age=14400`, 4 h) darauf, obwohl der Origin `no-cache` sendet (nachgemessen: Origin-Container lokal vs. Live-Antwort). Alte Tabs bekamen so stundenlang „MIME type text/html"-Modulfehler statt eines sauberen Scheiterns. Zwei Konstruktionsregeln daran: (1) der Miss verlässt die Location über `try_files $uri @assets_missing`, damit das 404 **nie** den `immutable`-Header des Treffer-Falls trägt — ein Deploy-Rennen (neue `index.html`, alter Pod) würde das 404 sonst ein Jahr festnageln; das 404 trägt explizit `no-cache` + den vollen Security-Header-Satz. (2) **Die CSP existiert seither GENAU EINMAL, als Konstanten-`map` `$vp_csp`** — drei Locations servieren sie, und die Smoke-Tests prüfen nur PRO Antwort die Anwesenheit, ein driftendes Duplikat wäre unsichtbar; die Allowlist wird also in der Map erweitert, nie an einer Location. Wächter: `test/cache-smoke.sh` Check 8 (404 + `no-cache` + Security-Header auf einem erfundenen `/assets/index-*.js`).
