Ausgelagert aus `frontend/portal/AGENTS.md` am 05.09.2026 (Abschnitt Nr. 1, Punkt 046).

- **Flow editor (E3a, Plattform → Flows, admin-only).** `pages/admin/FlowsPage.tsx` (Mandant→Anlage picker like OptimizerPage, flow cards + Vorlagen row, pilot template) opens `FlowEditorPage.tsx` in place (no deep link - the admin-console internal-state precedent). `FlowsPage` now builds an `adminFlowApi(tenantId,siteId)` and passes `api={...}` to the shared editor (see E3b). ALL rules live in the pure `src/flows/*` modules: `model.ts` (contract types, edit ops, D-13 `deriveClaims` incl. the plan-fed-suppression rule - the TS twin of the api's `FlowClaims`), `validate.ts` (V-1..V-8, twin of `FlowGraphValidator`, shared vectors in `validate.test.ts`), `layout.ts` (deterministic layered auto-layout - the flow-graph schema carries NO positions), `templates.ts` (pilot flow + card chain + sim line), `guardbar.ts`, `flowsApi.ts` (explicit X-Tenant-Id per call). `components/flows/FlowCanvas.tsx` is a hand-rolled SVG renderer (EnergyFlow approach): click-to-connect (output port → compatible inputs pulse green), SVG text needs manual `truncate()` (no clipping). The catalog is the SYNCED COPY `src/flows/catalog.json` of the api's `flowcatalog/catalog.json` (`catalog.sync.test.ts` drift guard - change both together). CSS block "Flow editor (E3a)" in `index.css`. Verified in-browser 1440/768/375 (canvas is the only horizontal scroller; the 375 admin-topbar overflow is pre-existing shell behavior).
