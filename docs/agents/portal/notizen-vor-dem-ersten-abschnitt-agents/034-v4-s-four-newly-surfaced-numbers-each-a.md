# v4's four newly-surfaced numbers, each a pure unit-tested derivation + a thin render

Ausgelagert aus `frontend/portal/AGENTS.md` am 05.09.2026 (Abschnitt Nr. 1, Punkt 034).

- **v4's four newly-surfaced numbers, each a pure unit-tested derivation + a thin render:** (1) **Plan-traf-zu** one-liner (`src/planAccuracy.ts` `planTrafZu(planAccuracy, now)` from the `forecast-quality` `plan_accuracy` series - accuracy = `1 - |realized-planned|/max(...)`, saved = `baseline-realized>0`; the page fetches `api.forecastQuality(siteId)`), rendered as the yellow `.vp-plantraf` button. (2) **Curtailment saved** (`src/schedule.ts` `curtailmentToday(slots, now)` needs the NEW backend `ScheduleSlot.curtailKw` - "heute X kWh abgeregelt, Y € Verlust vermieden", avoided loss only in negative-price slots). (3) **Weather "why"** (`src/weather.ts` `weatherWhy(points, now)` reads upcoming daytime cloud cover → "Sonnig bis 18 Uhr…"; shown only when the live snapshot is fresh). (4) **Control always honest** (`controlStrip(status, now, expectControl)` gained a `preparing` state - when `expectControl` (a plan with a `deviceId`) but no readback yet, it says "Die Steuerung wird vorbereitet…" instead of rendering nothing). The Gesundheits-Checklist is `src/health.ts` `healthChecklist(input)` (Gerät/Fahrplan/Steuerung/Speicher, warn-first sort, omits rows that would be dishonest). Deliberately NOT built: the §14a "Netzgrenze N× aktiv" chip (would need an extra telemetry fetch on the main page for a minor signal). The Fahrplan band (`components/FahrplanBand.tsx`) switches between the full `ScheduleChart` (`>=620px` container via `useContainerWidth`) and a compact 24-bar mini on phone.
