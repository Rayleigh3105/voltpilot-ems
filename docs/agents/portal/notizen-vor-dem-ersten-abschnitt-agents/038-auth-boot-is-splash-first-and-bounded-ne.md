# Auth boot is splash-first and BOUNDED - never render-nothing-until-init (white-page fix, vp-login-whitepage-q9, 2026-07

Ausgelagert aus `frontend/portal/AGENTS.md` am 05.09.2026 (Abschnitt Nr. 1, Punkt 038).

- **Auth boot is splash-first and BOUNDED - never render-nothing-until-init (white-page fix, `vp-login-whitepage-q9`, 2026-07-17).** keycloak-js 26's `init()` contains UNBOUNDED iframe/postMessage waits: a proxy/Keycloak ERROR page inside the hidden login-status or silent-check-sso iframe fires the iframe `load` event but never sends the postMessage keycloak-js waits for - with nothing rendered until init settles, that was the captain's intermittent permanent white page (repro: 502 on `login-status-iframe.html` -> `#root` empty forever). The structure that prevents recurrence: `main.tsx` creates ONE React root, renders `BootSplash` (`components/Boot.tsx`) synchronously, wraps every render in `BootErrorBoundary`, and bounds the whole `initAuth()` in `withTimeout(..., BOOT_TIMEOUT_MS)` from the pure `src/boot.ts` (`bootOutcome` = the unit-tested branching incl. loop-guard + rate-limit interplay). On timeout -> manual card "Die Anmeldung dauert ungewoehnlich lange" WITHOUT wiping stored state ("Anmelden" then does a clean full-page `login()`). `auth.ts` sets `checkLoginIframe: false` on the check-sso init (kills the login-status-iframe hang class; cross-tab logout degrades to refresh-failure -> re-login via `freshToken()`) and bounds token grants (`AbortSignal.timeout`); a 429/brute-force-locked refresh KEEPS the stored tokens, sets `wasRateLimited()` -> "Zu viele Anmeldeversuche" card, and `bootOutcome` never auto-redirects then. Corrupt `vp.auth.tokens` (incl. missing refresh_token) are logged + treated as absent. Do not add new awaits to the boot path without a bound, and never render nothing while awaiting. Tests: `boot.test.ts`, `auth.boot.test.ts`, `components/Boot.test.tsx`.
