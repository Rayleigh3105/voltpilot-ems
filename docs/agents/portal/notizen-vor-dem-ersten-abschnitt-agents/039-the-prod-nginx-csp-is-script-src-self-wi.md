# The prod nginx CSP is script-src 'self' WITHOUT 'unsafe-inline' - NO inline <script> may exist in anything nginx serves

Ausgelagert aus `frontend/portal/AGENTS.md` am 05.09.2026 (Abschnitt Nr. 1, Punkt 039).

- **The prod nginx CSP is `script-src 'self'` WITHOUT `'unsafe-inline'` - NO inline `<script>` may exist in anything nginx serves (CSP hotfix, 2026-07-17).** An inline script is SILENTLY blocked: `public/silent-check-sso.html` had one, its postMessage never fired, keycloak-js `init()` never settled, and every prod visitor hit the 10 s boot-timeout card (full login outage). The postMessage now lives in the external `public/silent-check-sso.js` - keep it external, and never "fix" a blocked script by adding `'unsafe-inline'` to script-src. The CSP is scoped to `location /` only (nginx `add_header` is per-location), so proxied `/auth/` (Keycloak) and `/api/` responses are untouched. **Guard: `npm run test:csp`** (`test/csp-smoke.sh`, wired into the deploy.yaml frontend gate) runs the REAL built nginx image and asserts: hardening intact, no inline scripts in served HTML, `/auth/` carries no portal CSP, and - when a Chrome binary exists - a same-origin harness iframing `/silent-check-sso.html` receives the postMessage within 3 s under the real headers. When the app grows a new external host (fetch/img/font), extend the nginx.conf CSP allowlist in the same PR.
