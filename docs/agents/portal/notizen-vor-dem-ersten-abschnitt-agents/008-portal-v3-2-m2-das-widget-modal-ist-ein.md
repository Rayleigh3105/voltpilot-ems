# Portal v3.2 · M2 — das Widget-Modal ist ein RICHES Detail-Modal (Werte UND Verlauf zusammen, OpenEMS-Richtung).

Ausgelagert aus `frontend/portal/AGENTS.md` am 05.09.2026 (Abschnitt Nr. 1, Punkt 008).

- **Portal v3.2 · M2 — das Widget-Modal ist ein RICHES Detail-Modal (Werte UND Verlauf zusammen, OpenEMS-Richtung).** Der frühere „Jetzt | Verlauf"-Umschalter im `WidgetModal` ist WEG: ein Tipp auf eine Kachel zeigt jetzt in EINER Ansicht die Werte der Kachel UND ein **Verlauf-Diagramm dieser Kennzahl über den GEWÄHLTEN Zeitraum** (Heute/Monat/Jahr/Gesamt). Kein neuer Chart-Stack — es reuse't die geteilte `useEChart`+`chartTheme`-Maschine (der `HistoryChart`-Pfad); der Energiefluss-Hero und die M1-Ring-KPIs sind UNANGETASTET.
  - **Die Verlauf-Ableitung ist das reine, unit-getestete `src/widgetHistory.ts` (`widgetHistory.test.ts`):** `widgetHistoryMetric(id)` ordnet nur den **Fluss-/Energie-Kacheln** (Erzeugung→`pvKwh`, Haus→`loadKwh`, Netz→`gridImportKwh`+`gridExportKwh`, Speicher→`socLastPct` %-Achse, Eigenverbrauch→PV+Last) eine Reihe zu — Handel/Erlöse/Lastspitze tragen ihre eigenen reichen Körper (`extra`), Automatik/Wetter haben hier keine Reihe → `null`, kein Diagramm. `widgetSeries(history, metric)` **folgt dem Zeitraum**: Tag → mittlere kW (Kurve, `kWh·60/bucketMinutes`), Woche/Monat/Jahr → kWh-Balken, Ladestand → %-Kurve. `metricHasData`/`noVerlaufNote` sind die „—"-Disziplin: kein Verlauf (Gesamt hat KEINEN Endpunkt, frische Anlage) → ehrlicher deutscher Satz statt eines erfundenen Diagramms, nie eine 0.
  - **Render-only:** `components/WidgetHistoryChart.tsx` (feeds `widgetSeries` an ECharts via `useEChart`, `.vp-chart-modal` mit `clamp`-Höhe im Container) + der umgebaute `WidgetModal` (Prop `jetztExtra`→`extra`, NEU `history`/`range`/`periodLabel`; rendert Werte-Zeilen + `extra` + `WidgetHistoryChart` + BEIDE Absprünge (`jetzt.drillIn` Technik + `verlauf.drillIn` Live/Historie, entdoppelt) in EINER Ansicht). `AnlagenPage` hält jetzt die volle `rangeHistory` (`History`) statt nur `rangeTotals` (ein Abruf speist Ringe UND Modal-Chart; `rangeTotals` daraus abgeleitet) und reicht sie ans Modal. CSS komponenten-lokal in `components/CockpitBlocks.css` (die `.vp-wmodal-seg*`-Regeln sind weg; NEU `.vp-wmodal-verlauf*`/`.vp-chart-modal`/`.vp-wmodal-noverlauf`); `index.css` unangetastet.
  - **Beweis:** `widgetHistory.test.ts` (Metrik-Zuordnung, `widgetSeries` folgt dem Range mit unterschiedlichen Einheiten/Daten, `metricHasData`/`noVerlaufNote`) + `components/WidgetModal.test.tsx` (Werte+Verlauf gemeinsam, KEIN Umschalter, Verlauf folgt dem Etikett, `history:null`→„kein Verlauf"-Satz, Gesamt beim Namen, Kachel ohne Metrik→kein Diagramm) + `pages/AnlagenPage.test.tsx` (Netz-Kachel öffnet das riche Modal, kein `.vp-wmodal-seg`). In Chrome (echtes `emulate`) bei 1440/768/375 gemessen: 0 px horizontaler Überlauf, 0 Offender, Modal am Telefon Vollbild, Diagramm im Container.
