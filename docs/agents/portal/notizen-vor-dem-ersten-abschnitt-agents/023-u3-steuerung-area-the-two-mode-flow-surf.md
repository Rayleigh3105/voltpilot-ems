# U3 "Steuerung" area = the two-mode flow surface with the editor as the STAR (design data/vp-ems-ui-overhaul/report.md §4

Ausgelagert aus `frontend/portal/AGENTS.md` am 05.09.2026 (Abschnitt Nr. 1, Punkt 023).

- **U3 "Steuerung" area = the two-mode flow surface with the editor as the STAR (design `data/vp-ems-ui-overhaul/report.md` §4, epic UO #514, builds on U1/U2).** `#/anlage/{id}/steuerung` (`pages/SteuerungSection.tsx`) is the ONE customer flow surface; `#/anlage/{id}/optimierung` is now a **redirect-only** route (`nav.ts` `LEGACY_SUBS = {optimierung: 'steuerung'}`; `optimierung` dropped from `AnlagenSub`/`SUBS`/the AnlagenPage sub-switch + DetailCard). The Optimierung content was **Level 1 "Was läuft"** (`<OptimierungSection>` rendered inside SteuerungSection; since the M2/Projektion rebuild nothing rendered it any more, and Stufe 0 of the Anwendungs-Programm DELETED the file — its pure copy layer `moduleSurface.ts` stays). **Level 2 "Ihre Steuerungen"** has two first-class mode tabs **⚙ Strategien | ⚡ Automationen** that open the **SAME `FlowEditorPage`** via `customerFlowApi` — NO fork — differing only in `paletteFilter` (new `FlowEditorPage` prop) + template set + list filter.
  - **The split is PRESENTATION only, keyed on whether the graph carries a `group==='strategie'` node** — pure, unit-tested `src/flows/steuerung.ts` (`flowMode`/`hasStrategyNode`/`paletteFilterFor`/`MODES`; `steuerung.test.ts`). Automationen palette = daten/logik/aktion (never a strategy node); Strategien palette = strategie + daten + aktion. No schema change, no second engine.
  - **The canvas is SHOWN, not hidden:** each flow card carries a read-only `FlowCanvas` preview (`.vp-flowpreview`, `pointer-events:none`, `CanvasPreview` with no-op handlers) via the deterministic `layout.ts`; opening a flow goes full three-pane.
  - **The guided Wenn/Dann + Zeitplan builder = the pure `src/flows/guidedBuilder.ts` + `components/GuidedRuleBuilder.tsx`.** `buildGuidedFlow(rule, name, siteId)` PROJECTS a `GuidedRule` (conditions[] × combinator × action) onto ONE `FlowDocument` from catalog nodes only; `parseGuidedFlow(doc)` is the round-trip / subset gate (null → open read-only in the Profi-Ansicht). **customerTemplates.ts now BUILDS its two E3b templates through `buildGuidedFlow` (shared emitter)**, so both are golden round-trip cases (`guidedBuilder.test.ts`). Condition kinds: entity(read→threshold), price(vp.price.current→threshold), schedule(window); actions: onoff/setpoint(→vp.logic.if)/notify(→vp.logic.gate→notify). **Footgun the tests caught: `Number('') === 0`** — an empty threshold/setpoint field must be rejected (`parseNum`), and `buildGuidedFlow` must be passed `siteId` or the emitted doc fails client validation (server stamps it on save, but the raw doc needs it to validate clean in a test).
  - **Profi-Ansicht ("voller Editor") is the same `FlowEditorPage`, write-gated via the EXISTING per-node governance** (gated strategy nodes locked until VoltPilot enables them; free device/logic/data nodes usable — the E3b capability is preserved, not regressed). The report's optional site-level "Profi-Editor" enablement flag is deliberately NOT built (a follow-up); reusing per-node governance satisfies "visible-but-gated" without a new backend table.
  - **New catalog nodes land in all three catalogs (api `flowcatalog/catalog.json` ⟷ portal `src/flows/catalog.json` ⟷ flowc `catalog.js`):** `vp.logic.and`/`.or` (bool combinators, two `a`/`b` inputs) + `vp.price.current` (current spot price as a `number`, ct/kWh, feeds threshold). `model.ts` `ID_PREFIX` gained them. Drift guard + `catalog.sync.test.ts` (structural `toEqual`) stay green. Backend detail (flowc schedule enum-days fix, FlowSimulationMapper mapping a device automation to the standardSpeicher baseline so it activates, the two fixtures + pinned hashes) is in the ROOT AGENTS.md "Flow-Editor" section.
