# Site location is a map with a draggable pin, not raw coordinate fields (components/LocationMap.tsx + pure components/geo

Ausgelagert aus `frontend/portal/AGENTS.md` am 05.09.2026 (Abschnitt Nr. 2, Punkt 059).

- **Site location is a map with a draggable pin, not raw coordinate fields (`components/LocationMap.tsx` + pure `components/geo.ts`).** ONE shared, controlled component for all three site forms - `CreateSiteDrawer` (customer + admin), `StandortePage` `SiteEditForm`, and `Onboarding` `SiteStep`. Parents hold coordinates as `number | null` and pass `{lat, lon, onChange}`; the component owns the Leaflet map (keyless OpenStreetMap tiles, `leaflet` npm dep - **portal only, never the edge app**), the readable coord line (via `fmtCoords`), and an expert "Koordinaten manuell bearbeiten" expander whose two fields stay in sync with the pin. No pin yet -> a DACH-level view (`geo.DACH_CENTER/ZOOM`) invites click-to-place; a pin -> a brand-navy DivIcon marker the user drags (`draggable:true`); the onboarding `LocationSearch` result just sets `lat/lon` and the map flies there (`PIN_ZOOM`) for fine-dragging. The pin is a CSS/SVG **DivIcon** on purpose - Leaflet's default PNG marker icons break under the bundler. `scrollWheelZoom:false` so the page still scrolls over the map; one-finger touch pans/drags (standard Leaflet handling); `.vp-map` sets `position:relative; z-index:0` to CONTAIN Leaflet's internal high z-indexes (zoom controls ~1000) inside the map box so they never float over a Modal/other cards.
  - **Pin<->field sync has no suppression flag** (an earlier `fromManual` ref got STUCK true when a manual edit resolved to the current value = a no-op `onChange` that React bails on, so the effect never ran to clear it, and the NEXT external change was swallowed). Instead the sync effect rewrites a field only when `fieldMatches(text, prop)` is false - so the text the user is actively typing (incl. a German `52,52` comma) is never reformatted under the cursor, and every external change (drag/search/clear) still syncs. Regression pinned by `LocationMap.test.tsx` "still reflects an external change after a manual edit that resolved to the same coordinate".
  - **Pin drags respond only to TRUSTED pointer events.** Leaflet's Draggable uses pointer capture, so synthetic `dispatchEvent(new MouseEvent/TouchEvent)` do NOT move the marker - a real CDP drag (`chrome-devtools-axi drag @from @to`, which Chrome routes through the same unified pointer path for mouse AND touch) does. Verify pin dragging with the native drag, not JS-dispatched events. Logic tests live in the pure `geo.ts` (`syncFromFields`/`parseCoordInput`/`isValidLat`/`isValidLon`); the component test mocks `leaflet` (needs real layout jsdom lacks).
