# Die HEIMAT einer Einstellung haengt nie davon ab, ob ein Modus laeuft (E1, Captain-Entscheid D1 vom 31.07.2026; Konzept

Ausgelagert aus `frontend/portal/AGENTS.md` am 05.09.2026 (Abschnitt Nr. 2, Punkt 070).

- **Die HEIMAT einer Einstellung haengt nie davon ab, ob ein Modus laeuft (E1, Captain-Entscheid D1 vom 31.07.2026; Konzept `data/vp-settings-ux-konzept/report.md` §3/§7).** Der behobene Fehler war STRUKTURELL: v3.1-M3 hatte die Geld-/Verhaltens-Einstellungen in die Modus-Container verschoben, und seit „Eigenverbrauch ist kein Modus mehr" beansprucht sie **nur noch `marktvermarktung`** — `settingsForMode` liefert aber nichts, solange der Modus aus ist. Auf einer gewoehnlichen PV-+-Speicher-Hausanlage war der **Stromtarif damit ueber KEINE Flaeche erreichbar**, obwohl der Optimierer mit ihm plant und jede Euro-Zahl mit ihm bewertet wird; die Sackgasse schloss sich, weil der Markt-Modus seinerseits einen dynamischen Tarif voraussetzt (einziger Ausweg war, die Anlage faelschlich zur Direktvermarktungs-Anlage zu erklaeren). Der Code kannte den Zustand beim Namen (`orphanedSettings`) und ein gruener Test hielt ihn woertlich fest.
  - **Die Regel steht in `modeSettings.ts` als `home`:** `'einstellungen'` = die Einstellungs-Seite BESITZT den Wert (`settingsPageSettings(ctx?)`, bewusst OHNE Modus-Argument), `'modus'` = er lebt weiter im Container (heute nur die drei von-VoltPilot-Werte der Lastspitzenkappung). `claimedBy` beantwortet seither „welcher Modus BRAUCHT diesen Wert", nicht mehr „wo darf man ihn aendern"; `orphanedSettings` kann eine Einstellung mit Heimat nie mehr zurueckgeben. **Eine neue Kunden-Einstellung bekommt `home: 'einstellungen'`** — sonst ist sie auf einer modus-losen Anlage sofort wieder unerreichbar.
  - **Es gibt GENAU EINE Bearbeiten-Stelle.** Die Formulare + die Zeile leben einmal in `components/SettingEditors.tsx` (`settingReadValue` · `SettingRow` · `canEditSetting`, CSS `SettingEditors.css` `.vp-setting-*`); die Einstellungs-Seite rendert sie mit `action={{kind:'edit'}}`, der Modus-Container mit `action={{kind:'link'}}` — read-only plus Deep-Link. Doppel-Editierbarkeit ist ausgeschlossen, nicht nur unerwuenscht. **Die Voll-Repraesentations-Falle ist mit umgezogen:** `buildSitePayload`/`saveBattery` tragen jedes Nachbarfeld unveraendert durch, sonst blankt ein fokussierter Save die Nachbargruppe.
  - **Verteilung nach dem Entwurf (§7 P4), nicht alles in einen Topf:** `pages/AnlageTechnik.tsx` bekam die neue Gruppe **„Strompreis & Vergütung"** (Stromtarif inkl. Bezugspreis-Komponenten · anzulegender Wert · Netzladen) direkt hinter „Meine Anlage"; der **„Umgang mit dem Speicher" gehoert zu „Mein Speicher"** — er ist eine Verhaltens-, keine Geld-Einstellung. Die Sichtbarkeitsregel bleibt unveraendert: der anzulegende Wert erscheint nur auf einer Direktvermarktungs-Anlage (`settingRelevant`).
  - **Der Deep-Link ist ein PARAMETER im Hash, kein zweites `#`** (`settingsNav.ts` `einstellungenHash`/`parseSettingsAnchor`, das `historieHash`-Muster): `#/anlage/{id}/technik?abschnitt=geld`. `parseRoute` schneidet den Query-Teil ohnehin ab, die Route bleibt also identisch — in `settingsNav.test.ts` festgenagelt. Die Seite liest ihn beim Aufbau UND bei `hashchange` (ein Klick aus einer schon offenen Anlage muss wirken), scrollt die Gruppe an und klappt sie am Telefon auf; `settingsGroupFor` gibt fuer alles ohne Heimat bewusst **null** zurueck — lieber kein Link als einer ins Leere.
  - **D2: die Seite heisst „Einstellungen".** Titel, Untertitel, Zahnrad-Knopf, „Mehr"-Karte, die Assistenten-Zusage (`AnlageFlow`) und der Eigenverbrauchs-Hinweis (`anlage.ts eigenverbrauchProvenance`) sagen das jetzt gleich — und die Zusagen stimmen wieder, weil Stromtarif und Verguetung dort auch wirklich stehen. Die Route (`sub: 'technik'`) ist unveraendert, jedes Lesezeichen gilt.
  - **Beweise:** `modeSettings.test.ts` (der frueher gruene „ALLE Einstellungen ruhen"-Test ist ins Gegenteil umgeschrieben: eine reine PV+Speicher-Anlage ERREICHT sie alle; Partition „erreichbar ODER verwaist"; Waisen tragen nur noch `home:'modus'`), `settingsNav.test.ts`, `pages/AnlageTechnik.test.tsx` (Gruppe auf der Eigenverbrauchs-Anlage, Voll-Repraesentations-Save, Deep-Link-Ziel), `components/ModusContainer.test.tsx` (Spiegel: kein Bearbeiten-Knopf, richtige Adresse je Gruppe, kein Link ohne Ziel). Im Browser gegen einen Wegwerf-Harness gemessen (1440/375): Tarif auf einer Eigenverbrauchs-Anlage eingegeben und gespeichert (PUT trug Name/Zone/Koordinaten/Einspeisegrenze unveraendert mit), Spiegel-Link → Gruppe angesprungen, 0 px horizontaler Ueberlauf.
