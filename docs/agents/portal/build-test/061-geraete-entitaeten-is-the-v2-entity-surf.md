# "Geräte & Entitäten" is the v2 entity surface (E1b).

Ausgelagert aus `frontend/portal/AGENTS.md` am 05.09.2026 (Abschnitt Nr. 2, Punkt 061).

- **"Geräte & Entitäten" is the v2 entity surface (E1b).** Anlage subpage `#/anlage/{id}/entitaeten` (`pages/EntitaetenSection.tsx`, reached via a `DetailCard` on the Anlagen-Seite): per-entity cards (type label, live health dot, capabilities, guard config) that are **read-only for customers**, plus the honest **Soll/Ist drift banner** (pending changes, entities not yet on the device, stale-on-device ghosts) and the **edge-local commissioning view** for everyone. Platform-admins get create/edit/delete via a `Modal` driven by the data-driven type catalog (composed pilot types are read-only). ALL copy/verdicts are the pure, unit-tested **`src/entities.ts`** (`syncVerdict` maps the 5 backend statuses → 4 badge tones, only `in_sync` green; `hasDrift`, `healthLabel`/`healthTone`, `guardRows` German limit labels, `entitiesSummary` — German OUTCOME language, no register/Modbus jargon; `entities.test.ts`). Types + reads (`siteEntities`/`entityHistory`) on `api.ts`; admin writes + type catalog in `src/entitiesApi.ts` (plain `request`, so the shell's `X-Tenant-Id` switcher applies for admin-in-customer-page, like optimizerApi). CSS block "Geräte & Entitäten (E1b)" in `index.css` (`.vp-entity-*`/`.vp-health-dot`/`.vp-chip-static`/`.vp-local-setup-*`; every card `min-width: 0`). Backend surface: root AGENTS.md "v2 entity model - generalization (E1b)".
