- **IA: ONE site = ONE Anlage (captain decisions 2026-07-07, "Anlagen-Seite" Phase A).** The customer nav is exactly `Übersicht / Meine Anlage(n) / Marktpreise / Prognosequalität` (+ the admin-only Plattform group); the old Standorte/Geräte/Live-Daten/Fahrplan/Wetter/Historie menu items are GONE - nothing was deleted, everything moved onto **the Anlagen-Seite** (`#/anlage/{siteId}`, `pages/AnlagenPage.tsx` `AnlageSeite`): one scrollable story in the captain's mockup order - Kopf (name + status dot + ONE `composeSiteSentence` + Anlagentyp/Netzladen badges), Geld (site-scoped `EarningsHero`), Jetzt (`EnergyFlow`; the live depth lives ON the page since the Cockpit+Live merge), Fahrplan-Mini (24 hourly bars + ONE derived German sentence + "Heute geplant: +X €"), Technik (`pages/AnlageTechnik.tsx` `TechnikSection`: Wechselrichter rows + device drawers, `BatteryControlSection`, MaStR block, "Standort & Einstellungen" incl. `SiteEditForm` + DangerZone - the whole former Standorte/Geräte drawer content), and the "Mehr" link cards (Historie & Erlöse, Wetter). The deep views live as **subpages** `#/anlage/{siteId}/fahrplan|historie|wetter|…` (`FahrplanSection`/`WetterSection`/`HistorieSection` - the former standalone pages, now site-scoped sections without pickers; the former `live` subpage merged into the cockpit, its hash redirects). The 1:1 rule is UI-hard only (no DB constraint; a multi-device site still renders all its devices in Technik, it just gets no UI promotion). Wording rule: new surfaces say "Anlage"; "Standort" survives only as the address inside Technik.
