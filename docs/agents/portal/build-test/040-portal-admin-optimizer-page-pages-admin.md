# Portal-Admin Optimizer page (pages/admin/OptimizerPage.tsx, Plattform nav optimizer, platform-admin-only).

Ausgelagert aus `frontend/portal/AGENTS.md` am 05.09.2026 (Abschnitt Nr. 2, Punkt 040).

- **Portal-Admin Optimizer page (`pages/admin/OptimizerPage.tsx`, Plattform nav `optimizer`, `platform-admin`-only).** The diagnose-&-tune surface over the merged PR #125 endpoints (backend detail in the root AGENTS.md "Portal-Admin optimizer surface"). ONE scrollable page: a **Mandant→Anlage→Tag→Lauf picker** (reuses `adminApi.listTenants`/`listSites`; a native date input bounded by the response's `firstRunDate`/`lastRunDate` picks the Europe/Berlin day, the Lauf select walks that day's `availableRuns` - the backend list is day-scoped via `?date=`, so runs from days/weeks ago are reachable; a day without runs renders an honest "Keine Läufe an diesem Tag" state with the picker still usable), then verdict banner → inputs-at-a-glance → "Der Plan" chart (`OptimizerPlanChart.tsx`: battery bars by `chargeKind` + spot line + real Bezug/Einspeisewert dashed overlays + SoC + a grid sub-track; bar click selects a slot) → "Diesen Slot erklären" (ct/kWh waterfall + the backend's German `whyText`) → objective KPIs → config/tune table. The page ends with the **Was-wäre-wenn-Vorschau** (`WhatIfPanel` + `WhatIfCompareChart`, design §4.3, BUILT): knobs (Verschleiß, Backup-Reserve, SoC-Band, Netzladen) plus a Speicherschonung preset row that only PREFILLS the wear field → "Neu rechnen" → a delta table and both plans in one chart. Four rules there are load-bearing and easy to break: an UNTOUCHED field must stay ABSENT from the request (`buildWhatIfRequest`), or the server's "solve it as configured" baseline stops being that and the delta becomes meaningless; the "Simulation - es wird nichts an die Anlage gesendet" banner is always visible (it is the reason the panel is safe, not a toast); a delta row is toned only where the direction IS a value judgement (more Ersparnis good, more Verschleiß bad - Durchsatz/Zyklen stay neutral); and a FAILED run drops the previous result instead of letting stale numbers answer the new question. The panel's knob inputs carry explicit `aria-label`s prefixed `Vorschau:` because the config table above owns the same four words. The compare chart is its own component but reuses `useEChart`/`chartTheme`/`chargeKind`/`ChartLegend` (variant solid, baseline a pale outline behind it) - a two-plan comparison is a different question from the single-plan diagnostic chart. All derivation/copy is pure in `src/optimizer.ts` (`optimizerWhatIf.test.ts`); backend detail in the root AGENTS.md "What-if re-optimize". Data-access uses the **`X-Tenant-Id` switcher** but passes the tenant EXPLICITLY per call: `optimizerApi.ts` sets the header in `init.headers` (which `api.ts request()` spreads LAST, so it wins over the shell's module-global override) - so the page is independent of whatever the top-bar switcher points at. **All money-shaped logic is the pure, unit-tested `src/optimizer.ts`** (`objectiveTotals`/`verdict`/`slotWaterfall`/`buildConfigRequest`/`notableSlots` - `optimizer.test.ts`; the what-if half in `optimizerWhatIf.test.ts`); the page + config PUT round-trip in `OptimizerPage.test.tsx` (mocks `OptimizerPlanChart` since jsdom lacks canvas). **Null discipline is load-bearing** (mirrors the backend): a `Double`/`BigDecimal` that arrives null (no persisted spot, pre-P2 wear, battery-less site) renders "—", never a fabricated 0 - `costEur`/`baselineCostEur` are the ASYMMETRIC real cashflows so their diff IS the real saving, `wearCostEur` is persisted separately so honest net = baseline − cost − wear. The config PUT is full-representation (an empty form field → `null` → CLEARS that override to the platform default); `buildConfigRequest` mirrors the server's SoC-band-window validation client-side (400 avoided), battery fields disable on a battery-less site (server 409), and the "Gespeichert" flash survives the post-save config reseed (don't clear `ok` in the config-sync effect; `ConfigPanel` is `key={siteId}` so state resets per site). CSS block "Portal-Admin Optimizer page" at the end of `src/index.css`.
