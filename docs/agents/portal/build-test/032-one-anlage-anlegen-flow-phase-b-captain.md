# ONE "Anlage anlegen" flow (Phase B, captain decision 5).

Ausgelagert aus `frontend/portal/AGENTS.md` am 05.09.2026 (Abschnitt Nr. 2, Punkt 032).

- **ONE "Anlage anlegen" flow (Phase B, captain decision 5).** Creating an Anlage is one sequenced flow - `src/components/AnlageFlow.tsx`: 1 · Anlage (Name + `LocationSearch` + `LocationMap` + Anlagentyp; Stromtarif (`TariffFields`)/anzulegender Wert/Netzladen collapsed behind "Feineinstellungen (optional)"), 2 · Gerät (Geräte-ID claim, skippable), 3 · Speicher (optional; `api.saveBattery` WITHOUT deviceId → the claimed inverter auto-links backend-side). Hosts: the first-run wizard `src/Onboarding.tsx` (welcome card, `waitForFirstData` → the "Ihr Gerät meldet sich…" poll) and `components/AnlageAnlegenDrawer.tsx` for existing customers (summary finish; **the host reload is deferred to drawer close** - reloading the site list mid-flow would re-render an empty-state host and unmount the drawer mid-step). Pure logic in `src/anlageFlow.ts` (`initialFlowStep` resume-at-Gerät, `parseBatteryForm`, `normalizeDeviceIdInput`/`DEVICE_ID_FIELD`/`DEVICE_ID_UNKNOWN_MSG`, `zoneForCountry` - unit-tested in `anlageFlow.test.ts`; the flow component in `AnlageFlow.test.tsx`). `CreateSiteDrawer` remains ONLY for the admin Mandanten page (cross-tenant admin API). **Single-Anlage customers reach a second Anlage via the always-visible "＋ Anlage hinzufügen" action in the shell header** (`AppShell` top bar, right of the breadcrumb; icon+label ≥720px, icon-only ≤720px with an `aria-label`, ≥44px touch target). They have no Übersicht/Anlagen-Liste, so this is their only obvious entry - reachable from every page without scrolling (the earlier quiet bottom-of-page "Sie haben eine weitere Anlage?" line was easy to miss and is now removed). Visibility is the pure `src/addAnlage.ts` `showAddAnlageButton({isAdmin, loaded, tenantReady, onboarding, siteCount})` - true ONLY for a customer with `siteCount === 1` (never admins, who provision via Plattform; never fleets `>= 2`, which already carry an "Anlage anlegen" button on the Übersicht + Anlagen-Liste - so no two competing buttons on one screen). `App.tsx` computes it, passes `showAddAnlage`/`onAddAnlage` to `AppShell`, and hosts the SAME `AnlageAnlegenDrawer` one-flow as everywhere else (on finish: `reload(createdSiteId)` + `navigate(anlageRoute(createdSiteId))` lands the customer on the new Anlage). Unit-tested in `addAnlage.test.ts`; the render/click in `shell/AppShell.test.tsx`.
