# Probe-Kanal: die Einmal-Anfrage Cloud→Box (Einheitsmodell Stufe 0b)

Ausgelagert aus `AGENTS.md` am 05.09.2026 (Abschnitt Nr. 19).


Der Unterbau, aus dem später jede Live-Vorschau und jeder Verbindungstest des Anlege-Assistenten lebt (Konzepte `vp-komponenten-einheit-h2` §8 Stufe 0b, `vp-modbus-baukasten-k6` §2.5/§2.6): das Portal bittet die Box, ein Gerät im KUNDEN-LAN einmal zu lesen, und bekommt Roh- UND dekodierten Wert zurück. Reiner Unterbau — **es gibt noch keine Kundenfläche**, und der Kanal hat KEINEN Schreibpfad.

- **Vertrag `docs/contracts/mqtt-probe.schema.json`** (+ 3 gültige / 1 ungültige Fixture, per PFAD gelesen): zwei Nachrichten im per-Gerät-ACL-gedeckten `v2/#`-Teilbaum (D-2, **keine Broker-Änderung**) — `…/v2/probe` (Cloud → Edge) und `…/v2/probe-result` (Edge → Cloud), korreliert über `request_id`. **NICHT-retained in beide Richtungen**, aus demselben Grund wie die OTA-Einmal-Freigabe: eine retained Vorschau klopft bei JEDEM Reconnect erneut an einem Kundengerät an. **⚠ Nicht-retained allein genügt nicht** — die Box hält eine dauerhafte Sitzung, der Broker darf QoS1 nachliefern, also ist `requested_at` die zweite Hälfte: die Box übernimmt diesen Stempel als Beginn ihres 60-s-Fensters statt des Empfangs-Zeitpunkts, eine nachgelieferte Anfrage ist bei der Ankunft also bereits verfallen und wird VERWORFEN.
- **Der Op-Typ `switch_test` ist VOLLSTÄNDIG spezifiziert und wird VALIDIERT, aber NICHT ausgeführt** (ehrliches `not_supported`). Er gehört zum Freigabe-Assistenten (Stufe 4); ein Vertrag, der ihn erst dann kennt, hätte eine Box im Feld, die eine ihr unbekannte Form still verwirft statt sie zu benennen. V1 führt genau `read` über `modbus_tcp` aus.
- **Die Regeln liegen in `edge-app/core/internal/probe` (rein, keine I/O, jede zeitabhängige Funktion nimmt `now` — das `otaapply`/`calibration`/`curtailcal`-Muster);** `agent/probe.go` ist ausschließlich Verdrahtung. Vier Zulassungsregeln: **Identität** (Topic == Payload, verworfen STUMM — eine Antwort bestätigte einem falsch adressierten Absender die Existenz des Geräts), **Verfall** (s. o., ebenfalls stumm), **privates Ziel** — eine Whitelist dessen, was sich aus der Zeichenkette BELEGEN lässt: private IP-Bereiche (RFC1918/loopback/link-local/ULA/CGNAT) oder ein Name mit LAN-Endung (`.local`/`.lan`/`.home.arpa`/…). **Ein NACKTER Hostname wird bewusst abgelehnt** — er wird über die Suchdomänen der Box aufgelöst, ist also nicht nachweisbar privat, und eine Whitelist, die ihr eigenes Versprechen nicht prüfen kann, ist keine; die Ablehnung nennt den Weg (die IP eintragen). Eine Blacklist wäre eine Adressklasse davon entfernt, falsch zu sein — ohne diese Regel wäre der Kanal ein Portscanner, den ein Portal-Fehler aufs offene Internet richten könnte) und **Ratenbegrenzung** (12/min, am anderen Ende hängt ein echtes Modbus-Gerät). **Die Ratenbegrenzung wird als EINZIGE BEANTWORTET** (`rate_limited`): sie ist unsere Entscheidung, nicht die des Geräts, und der Assistent muss sagen können, warum nichts kommt. Dazu die Kennungs-Eindeutigkeit über die Ops hinweg — die `id` ist das EINZIGE, was eine Antwort auf ihre Frage zurückbildet.
- **⚠ Der Core öffnet KEINEN eigenen Modbus-Socket** — die Lesung läuft über den lokalen Bus (`edge/probe/request|result`) zum Palette-Knoten **`vp-modbus-probe`** (Palette **0.6.0**, selbstständig im Tab „Verbindung testen", keine Verdrahtung, keine eingebettete Kopie). Dort wohnt `lib/modbus-conn.js`: EIN in-flight-Vorgang je (host, port) über ALLE vp-modbus-Knoten. Viele Kundengeräte (Solarman-Logger, billige Gateways) bedienen genau einen TCP-Client und verdrängen den laufenden — eine Vorschau mit eigenem Socket wäre also der Abbruch des Polls genau des Geräts, auf das der Kunde schaut. Gepinnt von `TestProbeNeverDialsTheDeviceFromTheCore` (echter Listener, der NIE verbunden werden darf) und dem Palette-Test „shares the ONE per-target queue with vp-modbus-read".
- **Fehler-Klassen sind das `testconn`-Vokabular** plus genau zwei eigene (`not_supported`, `rate_limited`); der Knoten klassifiziert auf der GESCHLOSSENEN Fehlermenge der zwei Module, die uns gehören (`modbus-conn` + `parseReadResponse`), nie auf unscharfe Regex über errno-Texte. **Ein Fehlschlag trägt NIE einen Wert**, ein Erfolg trägt raw UND dekodiert nebeneinander (der Moment, in dem ein Skalierungsfehler sichtbar wird) — und die api ERZWINGT das beim Ingest, statt es zu glauben (`ok` ohne beide Zahlen ist kein Messwert).
- **api: `POST /api/v1/sites/{siteId}/modbus-probe`** (`SiteProbeController`, RLS-gefenced wie jede `/sites/**`-Route — kein `@PreAuthorize`, fremde Anlage 404), synchron mit ~5 s Timeout, **kein Persistieren**: `ProbeRegistry` (in-memory, das `SimulationJobRegistry`-Muster — **das GERÄT ist Teil des Schlüssels**, ein fremdes Gerät kann eine Anfrage nie beantworten), `ProbePublisher` (nicht best-effort: die Nachricht IST die Frage), `ProbeResultListener` auf `ems/+/+/+/v2/probe-result`. Ein Timeout ist ein **ehrlicher AUSGANG** (HTTP 200 + `errorCode: timeout`), kein Fehler. Welches Gerät gefragt wird, wird **nie geraten**: mehrere Geräte ohne Auswahl sind ein benannter 409.
- **Keine neue Pflicht-Variable:** Publisher und Listener hängen an `voltpilot.provisioning.enabled` (derselbe Broker wie Provisionierung, Registry-Push und OTA-Verteilung) — bewusst KEIN eigenes, per Vorgabe ausgeschaltetes Flag, das im gitops-Repo nachgezogen werden müsste (die dokumentierte OTA-Listener-Falle).
- **⚠ Die LAN-Adresse des Kunden landet in KEINEM Protokoll** (Netz-Topologie; sie erscheint auf diesem Pfad in keiner anderen Zeile). Gepinnt von `ProbeApiTest.theCustomersLanAddressNeverReachesTheLog` — der Test schaltet `com.voltpilot.api` auf TRACE und liest die aufgezeichneten Zeilen zurück.
- **Beweise:** rein Go `internal/probe` (Parsen, die vier Regeln, Eindeutigkeit, Kontrakt-Fixtures per Pfad) + `agent/probe_test.go` (15: fremde Identität/Verfall/Rate-Limit/öffentliches Ziel erreichen das Gerät nie, `switch_test` vergiftet seinen Nachbarn nicht, raw+skaliert+Registerwörter, Klassen verbatim, kein Lese-Flow ⇒ `timeout`, **der Core wählt nie selbst**, Duplikat-Kennung, die Fixture durch den echten Handler, **der Router blockiert nicht**, **eine gleichzeitige Doppel-Zustellung liest EINMAL**) · Palette `test/probe_spec.js` (8, inkl. der geteilten Warteschlange gegen ein in-process-Gateway) · Java rein `ProbeResultListenerTest`/`ProbePublisherTest`/`ProbeRegistryTest` (20) · Testcontainers `ProbeApiTest` (6: die Reise Portal→Gerät→Kunde, ehrlicher Timeout, RLS-404 + anonym 401 ohne dass das Gerät gefragt wird, Geräte-Auflösung, Form-Ablehnungen, kein Log-Leak).
