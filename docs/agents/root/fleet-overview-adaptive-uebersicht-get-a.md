# Fleet overview (adaptive Übersicht): `GET /api/v1/overview` + `site.plant_kind`

Ausgelagert aus `AGENTS.md` am 05.09.2026 (Abschnitt Nr. 63).


Phase 1 of the multi-site fleet overview (plan/decisions: firstmate `vp-multisite-overview-k4`; Phase 2 - the realized earnings engine - and Phase 3 - negative-price curtailment + Marktprämie - are BUILT, see their own sections below).
The Übersicht is now ADAPTIVE: `sites.length > 1` renders the fleet mode (money hero on the brand gradient, fleet status sentence, per-site cards); tapping a card drills into the single-site body with a "‹ Alle Standorte" back affordance.
Since Phase 2 the hero shows MEASURED money (single-site customers get the same hero); the ex-ante planned number lives on the Fahrplan page only.
No Ø-Preis KPI in fleet mode (captain decision - meaningless across bidding zones).

- **`site.plant_kind`** (migration `V20260706010000`; enum-like TEXT `direktvermarktung | eigenverbrauch`, default `eigenverbrauch`): steers the money WORDING per site - Direktvermarktung says "Mehrerlös / mehr verdient" (spot revenue is literal income), Eigenverbrauch says "Vorteil / gespart"; a MIXED fleet gets the neutral "Ihr VoltPilot-Vorteil" headline while each site card keeps its own wording (captain decision 1, 2026-07-06).
  Exposed on `SiteDto.plantKind`, editable through the normal create/update site paths (`CreateSiteRequest`/`UpdateSiteRequest`, validated; the portal site forms have an "Anlagentyp" select).
  Pure additive ALTER - no infra bootstrap mirror needed.
- **`GET /api/v1/overview`** (`OverviewController` + `OverviewRepository`, RLS-scoped app datasource - the aggregation deliberately has NO tenant/site predicate, RLS is the fence; admins use the `X-Tenant-Id` switcher like every customer endpoint): per site `{plantKind, deviceCount, onlineCount, waitingCount, worstStatus, lastSeenAt, live (newest telemetry row via a top-1 LATERAL per site), plannedSavingsTodayEur}` plus fleet `totals` and `dailySavings` (14 Berlin days for the hero mini chart).
  Semantics worth knowing: device liveness derives from `max(received_at)` per device (the store-and-forward rule; the 5-min window MUST stay in sync with `api.ts ONLINE_WINDOW_MS`); `worstStatus` = stale beats waiting beats online; `plannedSavingsTodayEur` is the ex-ante `HistoryRepository.savings` semantics (DISTINCT ON latest run per 15-min slot) over the Europe/Berlin day computed SERVER-side - this replaced the old client-side `toDateString()` slot summing in the Übersicht and its browser-local-timezone day boundary; null = "no plan", never a fake zero.
  **U5 portfolio additions (additive, same RLS fence):** per site `roleCounts` (Σ v2 entities per topology role, `entity_type`→catalog category→role: storage→storage/producer→pv/meter→grid/consumer→consumer, one entity counted once) + `usageProfile` (the effective AE7 profile, the SAME `UsageProfileDeriver` the profile endpoint runs, fed the site's entity mix + ACTIVE-flow strategy nodes + money master data), both derived in ONE round trip (`OverviewRepository.entityTypeCountsPerSite`/`activeFlowDocumentsPerSite`); plus fleet Σ `storageCapacityKwh`/`storagePowerKw` on `totals` (from the v1 `asset` battery rows, `storageTotals()`; null when no battery). Feed the Betreiber Portfolio page (frontend/portal AGENTS.md "U5 Betreiber PORTFOLIO shell"). Proven by `PortalApiTest.overviewCarriesPerSiteRoleCountsUsageProfileAndStorageTotals`.
- **Portal:** pure fleet logic in `src/fleet.ts` (wording per fleet composition, `composeFleetSentence` - green when all fine, ONE silent device turns it amber and NAMES it (captain decision 8), `siteLiveFresh` = online device AND fresh observation, so a replaying store-and-forward edge never renders old values as live); render-only components in `src/components/FleetOverview.tsx` (hero with ~0.8 s count-up + 14-day spark bars, status card, site cards with the `--vp-flow-*` channel hues); the adaptive split + drill-down state live in `UebersichtPage.tsx` (`FleetUebersicht` / `SingleSiteUebersicht`).
  Fleet CSS is the "Fleet overview" block in `src/index.css`; cards are 1-up phone / 2-up ≥720px / 3-up ≥1200px, hero+status side by side ≥1024px.
