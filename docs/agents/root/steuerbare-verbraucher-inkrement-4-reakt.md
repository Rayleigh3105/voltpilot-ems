The FOURTH increment (docs/verbrauchssteuerung.md §13.2-§13.4, §5.1/§5.3, §11, §16, §19; contract decision **D-19**): an active `consumer_policy` becomes ONE generated edge flow that evaluates LOCAL signals reactively, activation/pause/deactivate are real portal actions, and §13.4 events trigger an on-demand replan. **Everything is behind flags, default OFF** (`VOLTPILOT_CONSUMER_CONTROL_ENABLED` + `VOLTPILOT_CONSUMER_POLICY_COMPILER_ENABLED`; both composes pass them `:-false`) - with the flags off every surface is byte-identical to Inkrement 1-3, and **the STOP path is deliberately flag-INDEPENDENT** (Flag aus ≠ gestoppt - the OTA/flow lesson): deactivate/pause always retire the policy AND retract the retained artifact.

- **D-19 (contract decision, `docs/contracts/v2/README.md`): the generated flow carries a server-stamped `origin` marker** (`{kind:"consumer-policy", policy_id, policy_version, entity_id}` on the flow-graph document - `FlowService.stampedDocument` REFUSES a customer document carrying one), the catalog node **`vp.consumer.reactive` is generated-only** (all THREE catalogs in lockstep: api/portal `generated:true, customer_visible:false`, flowc refuses the node in a document WITHOUT consumer-policy origin - the palette never offers it, `diagnosticOnlyTypes` pins it), and **`override` is RESERVED to the compiler**: `vp.entity.control` has no free override switch (validator twins + flowc push the German refusal), so the D-5 boost can only ever come from a validated `enforcement=must_run`.
- **Policy compiler = the CLOUD half** (`consumers/ConsumerPolicyCompiler`, pure + golden-tested; `PriceWindowSource` prices via the ONE `SlotEconomics` composition): D1 - price/time conditions become PRECOMPILED UTC windows (36-h horizon), local signals (`site.pv_surplus_kw`, `storage.soc_pct`, `consumer.vehicle_connected`, …) stay reactive at the edge with `max_age_s` + hysteresis. `generatedFlowId(entityId)` is a UUIDv3 of the entity (idempotent upsert via `FlowRepository.upsertGenerated`), the flow derives EXACTLY ONE entity claim (V-5 preserved), and a policy with no local-signal requirement compiles to NO artifact (windows-only rules ride the optimizer, `needsArtifact`). Determinism is pinned by the committed golden `golden-generated-flow.json` (compare via `toString()` - Jackson reads golden numbers as DoubleNode, the compiler builds DecimalNode).
- **Activation is §11 ATOMIC** (`ConsumerPolicyActivationService.activate`, routes on `SiteConsumerController`: `POST …/policy/activate|policy/deactivate|pause|resume`): connection check (422) → flag gate (honest `activated:false` envelope, the flows pattern) → validate (400) → compile → V-5 foreign-claim check (409) → flowc compile (**503 leaves the active version UNCHANGED**) → atomic retire+activate+deploy → republish (503 if an artifact exists but did not publish). Every change is audited (`consumer_audit_event`, migration `V20260812000000` - RLS + FORCE; ⚠ the BIGSERIAL needs its OWN `GRANT USAGE ON SEQUENCE`, the rollout_event footgun). `ConsumerDto.controlActivation` is DERIVED (active policy + enabled = `active`, + disabled = `paused`, else `not_activated`) - never hardcoded, so the row cannot lie after an activation.
- **Edge: the reactive engine is PURE and shared-shaped** (`edge-app/nodered/vp-palette/lib/reactive-eval.js`, consumed by the generated `vp-consumer-policy` node): Kleene 3-state logic (**unknown NEVER starts a consumer**, a stale signal is unknown - never 0), hysteresis via `reset_value`, off-delay debounce (a flickering `vehicle_connected` does not stop the charge mid-blink; ending only, starting is immediate and only from `true`), and precompiled windows where AFTER the last window = unknown (an expired window never restarts a rule, §13.5). Booleans ride entity telemetry as 0/1 channels. **Withdrawal is the ABSENCE of renewal**: the node publishes the desire with a SHORT continuously renewed TTL (`renew_s ≤ ttl_s/2`, flowc-validated) and simply stops when the condition ends - desires are never retained, there is no release message to lose.
- **The override chain is NOT loosened** (`edge-app/core/internal/desired/reactive_chain_test.go`): a must_run override preempts the PLAN (market) and withdraws by TTL; it NEVER preempts grid/contract (rejected `arbitration:priority`, the compliance command stands); the 4-h cap holds end to end (asked-for 6 h count for nothing); and an override runs the SAME consumer clamp + cycle guard (a 22-kW wish lands at the 11-kW band, a min-off pause holds an override restart with `guard_min_off`).
