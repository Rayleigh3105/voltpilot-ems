# Money-centric "Meine Anlage" v2 (`GET /api/v1/earnings` money-view fields + `site.tarif_art`/`tarif_param_ct_kwh`)

Ausgelagert aus `AGENTS.md` am 05.09.2026 (Abschnitt Nr. 70).


Captain feature 2026-07-07 (`vp-anlage-money-view`, modelled on the Deye Copilot app): the per-Anlage page leads with the **Gesamtertrag** in euros, period tabs govern the whole page, a tappable 12-month strip, an Ertrag chart. The portal side is in `frontend/portal/AGENTS.md` ("Meine Anlage v2" + "Single-plant merge"); the backend extends the existing PR-93 earnings engine (same files, additive). The tariff model + Nachvollziehbarkeit below (task `vp-anlage-nachvollziehbar`, 2026-07-08) supersede the original fixed `strompreis_ct_kwh`.

- **Tariff model `site.tarif_art` + `site.tarif_param_ct_kwh` (api migration `V20260708010000`, task `vp-anlage-nachvollziehbar`) - REPLACES the fixed `site.strompreis_ct_kwh`.** A single fixed retail price is wrong for the many customers on a DYNAMIC tariff (price changes every quarter hour; only the anzulegender Wert is truly fixed). Cleanest schema = ONE enum + ONE numeric (not two fixed/dynamic numerics): `tarif_art` is `dynamisch | fest | ohne` (default `ohne`), `tarif_param_ct_kwh` is its parameter - the fixed retail price for `fest`, the OPTIONAL spot-price Aufschlag (grid fees/levies/margin) for `dynamisch`, unused for `ohne`. The migration copies the old `strompreis_ct_kwh` into `fest` + that value (null -> `ohne`, the least-surprising default that reproduces the kWh-only behaviour) and DROPS the column (unlike the deprecated `marktpraemie_ct_kwh`, strompreis IS faithfully migratable, so it is migrated + dropped, no dead column). Pure additive ALTER (V2 RLS/grants cover it); on `SiteDto` + `CreateSiteRequest`/`UpdateSiteRequest` (validated; `tarif_art` overwrites like `plant_kind`, `ohne` clears the param via `tarifParamOrNull()`) + `AdminSiteRepository`; edited in the portal via the shared `components/TariffFields.tsx` on the SETTINGS/Technik subpage ONLY (captain decision 5 - the money view shows only results), NOT the money hero. Dev seed `db/dev/V20260708010100` sets Hof Lindenberg to `dynamisch` + 18 ct/kWh Aufschlag.
- **`EarningsController`/`EarningsRepository` per-site fields** (all null when nothing computable, same `reason`): `einspeiseErloesEur` (metered export x spot + Marktprämie - the feed-in revenue), `selbstverbrauchKwh` (= `greatest(load - grid_import, 0)`), **`eigenverbrauchsWertEur`** - now computed SLOT-BY-SLOT in the repository per the site's tariff (`EIGENVERBRAUCHS_WERT_EUR` SQL): `dynamisch` = `sum(selbstverbrauch_kwh * (price_eur_mwh/1000 + Aufschlag/100))` so each self-consumed kWh is valued at ITS OWN 15-min Börsenpreis + the fixed Aufschlag (the whole point - NOT a single flat price; the spot part can go negative in a negative-price slot, which is correct - the §51 suspension is a feed-in rule, not a self-consumption one); `fest` = `sum(selbstverbrauch_kwh * price/100)`; `ohne` = NULL (never a fabricated euro). Because it needs the per-slot spot price it MUST live in SQL, not the controller - the old `selbstverbrauchKwh x strompreis` controller helper is gone. `gesamtertragEur` = `einspeiseErloesEur + (eigenverbrauchsWertEur ?? 0)`; `eingespeistKwh`/`batterieBewegtKwh` (energy sums), `tarifArt`/`tarifParamCtKwh` (echo, so the portal can render the provenance sentence), plus `series` + `monthlyStrip` (both carry the tariff-priced Gesamtertrag per bucket). `BucketPoint` now carries `eigenverbrauchsWertEur` per bucket (SQL-computed) instead of raw `selbstverbrauchKwh`.
- **Nachvollziehbarkeit (captain decision 3):** each euro figure in the money hero carries an expandable `InfoTip` whose ONE German sentence names the real quantities + prices - pure builders in `src/anlage.ts` (`einspeiseProvenance`/`eigenverbrauchProvenance`/`gesamtertragProvenance`/`savedProvenance`, unit-tested in `anlage.test.ts`): e.g. "Selbst verbrauchte 97,3 kWh × dynamischer Börsenpreis + 18,0 ct/kWh Aufschlag (im Schnitt 27,3 ct/kWh)" - the effective average is derived from `eigenverbrauchsWertEur/selbstverbrauchKwh`, so the copy is real not hardcoded. The Ertrag chart gained a "Was zeigt das?" `ChartSubtitle` (Ertrag = Einspeisung + Wert des Eigenverbrauchs) + the best-bucket moved into a `ChartInsight`. The three energy tiles renamed to "Eingespeist / Selbst genutzt / Über Batterie" + a one-line hint each (`energyTiles()` in `anlage.ts`). Read-only Technik row via `fleet.ts tarifArtLabel`.
- **`EarningsRepository.bucketed(from, to, Bucket)`** buckets Gesamtertrag parts (`einspeiseErloesEur`/`selbstverbrauchKwh`) by Europe/Berlin **HOUR/DAY/MONTH** - one method, called twice: the range series (hour for day, day for month, month for year/all) and the 12-month strip (month buckets over the last year, anchored on today independent of `at`). Bucket start = `date_trunc(<unit>, r.bucket AT TIME ZONE 'Europe/Berlin') AT TIME ZONE 'Europe/Berlin'` (guaranteed correct across DST/month-length, no TimescaleDB month-bucket dependency; the unit is a fixed enum literal, never client input). `GET /earnings?range=&at=` already existed; the portal passes `at` for a strip-tapped past month.
- **Tests:** `PortalApiTest.earningsExposeGesamtertragEnergyAndSeriesForTheMoneyView` (hand-computed two current-month CH slots, a `fest` 30 ct/kWh tariff + an `ohne` twin: einspeise/selbstverbrauch/eigenverbrauchsWert/Gesamtertrag reconciliation `gesamt == einspeise + eigenverbrauchsWert`, energy sums, DAY series + month strip, the `ohne` kWh-only regression, RLS) + **`earningsValueDynamicSelfConsumptionSlotBySlotAtSpotPlusAufschlag`** (three CH slots at 100/200/-40 EUR/MWh with an 18 ct Aufschlag - proves the value follows each slot's spot price and differs from a `fest` twin with identical measurements; the negative slot proves the spot part goes down while the Aufschlag keeps it positive; a previous-month slot the range=month window excludes). Portal `anlage.test.ts` (provenance sentences incl. the dynamic average, energy-tile copy) + `fleet.test.ts` (`tarifArtLabel`). Verified end-to-end in the browser against an isolated stack (1440/768/375): the money hero with real numbers, the `eigenverbrauchProvenance` InfoTip showing "Selbst verbrauchte 97,3 kWh × dynamischer Börsenpreis + 18,0 ct/kWh Aufschlag (im Schnitt 27,3 ct/kWh)" clamped within the 375 viewport, the Tarif-Art form on the Technik gear subpage, and zero horizontal overflow.
