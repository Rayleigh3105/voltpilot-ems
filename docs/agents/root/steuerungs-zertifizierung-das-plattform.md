# Steuerungs-Zertifizierung: das PLATTFORM-Register (einmal pro Modell, nie wieder pro Kunde)

Ausgelagert aus `AGENTS.md` am 05.09.2026 (Abschnitt Nr. 16).


Captain-Order 10.08.2026, wörtlich: „der Kunde hat auch einen Deye und da muss ich die Steuerung freigeben, obwohl ich das schon mit einem anderen Kunden gemacht hab — ich hätte gedacht das merken wir uns". **Die Freigabe eines Wechselrichter-MODELLS für die Batterie-Steuerung landete bis dahin an genau zwei Orten, und keiner davon war die Plattform:** die flottenweite env-Allowlist `VP_CONTROL_CERTIFIED_FAMILIES` (auf die REGISTERFAMILIE geschlüsselt — übergriffig, weil eine Familie mehrere Baureihen abdeckt — und nirgends nachlesbar) oder die First-Light-Freigabe in `calibration-certified.json` auf GENAU EINER Box. Diese Runde fügt den dritten, dauerhaften Ort hinzu.

- **DREI Zertifizierungsquellen, ODER-verknüpft — deshalb ist der Umbau für jede Bestandsanlage byte-genau folgenlos.** Die EINE Stelle ist `agent.controlCertified` (`edge-app/core/internal/agent/calibration.go`): env-Allowlist ODER lokale First-Light-Freigabe ODER **Plattform-Register**. Eine neue Quelle kann damit nur HINZUFÜGEN; ein leeres Register und ein retained-clear nehmen einer Box ihren lokalen Grant nie.
- **ZWEI Halbwahrheiten, eine Freigabe.** `inverter_control_certification` (Migration `V20260814000000`, global ohne RLS wie `edge_release`/`provisioned_device`/die Rollout-Tabellen) sagt „Modell X ist am Prüfstand freigegeben" — EINMAL, flottenweit; `device_control_activation` sagt „Anlage Y darf das nutzen" — ausdrücklich, je Anlage. **Das Register allein steuert nichts**; deshalb sind es zwei Tabellen und kein Flag (eine Aussage über ein PRODUKT vs. eine Entscheidung über eine KUNDENANLAGE). Die ANWESENHEIT der Aktivierungszeile IST die Scharfschaltung — kein `activated BOOLEAN`, das auf false stehen und trotzdem Historie vortäuschen könnte.
- **⚠ Der Schlüssel ist brand+MODELL, nie die Familie.** `hybrid_3p` meint die LV-SG04LP3 UND die HV-SG01HP3 mit verschiedener Leistungsskala; ein Prüfstandslauf deckt genau ein Modell. Das Register ist damit strikt FEINER als die env-Allowlist, die es ablöst. Die Familie wird MITgeprüft (nicht abgeleitet): dasselbe Modell unter einer anderen Registerkarte ist nicht, was der Prüfstand belegt hat.
- **⚠ FIRMWARE ist Klartext, kein Maschinen-Tor** (`firmware_note`). Die Box liest keine Firmware-Version aus dem Wechselrichter, ein Firmware-Fenster wäre eine Zusage, die niemand prüfen kann. Die zwei firmware-abhängigen Dinge sind anderweitig abgesichert: das SCHREIB-VORZEICHEN über das optionale `invert_control_sign` (das GERÄT prüft es gegen seine eigene Einstellung und fällt bei Widerspruch fail-closed), die Verfügbarkeit des Deye-Remote-Modus über die laufende Fähigkeitsprüfung von Layer 1 (erkannt, nie angenommen). **`NULL` und `false` sind dabei VERSCHIEDENE Aussagen** — NULL heißt „der Lauf hat die Frage nicht beantwortet" (dann prüft das Gerät nichts), false heißt „er hat sie beantwortet"; der Publisher lässt NULL deshalb WEG statt es als false zu senden.
- **DIE ENTSCHEIDUNG FÄLLT AUF DEM GERÄT** (die OTA-Sidecar-Disziplin „der Sidecar glaubt dem Kern nichts"): die Cloud sagt, WELCHE Modelle gedeckt sind, die Box vergleicht das mit ihrer EIGENEN Auswahl. Deshalb reist das ganze (kleine) Register mit, statt dass die Cloud rät, welches Modell hinter einer Box steckt. Reine Regel: `edge-app/core/internal/controlcert` (`Parse`/`Match`, vier Urteile `granted` · `covered_not_activated` · `not_covered` · `unknown`).
- **Verteilweg: retained (QoS1) auf `ems/{t}/{s}/{d}/v2/control-certification`** (Kontrakt `docs/contracts/mqtt-control-certification.schema.json` + 3 Fixtures), im `v2/#`-Teilbaum, den die per-Gerät-ACL längst abdeckt (D-2) — **keine Broker-Änderung**. Retained ist der ganze Mechanismus: eine Box, die beim Scharfschalten offline war, holt das Dokument beim nächsten Verbindungsaufbau selbst ab. Leere Nachricht = Rücknahme (Unclaim). Das Dokument geht an JEDES beanspruchte Gerät, nicht nur an die scharfgeschalteten — **nur so kann eine Box selbst berichten, ob ihr Modell gedeckt ist**, und genau diese Unterscheidung ist der Auftrag; ein Dokument mit `activated:false` steuert nichts. Ausgelöst von jeder Register-/Aktivierungs-Änderung plus einem `ApplicationReadyEvent`-Abgleich (deshalb braucht der Claim-Pfad keinen Haken).
- **Der Rückkanal macht „wird vorbereitet" ehrlich.** Der Herzschlag trägt additiv `control.cert_source` (`env`|`device`|`platform`) und `control.platform_cert` (verdict/model/reason) — beides aus dem KERN, nie aus einem Layer-1-Stempel (die Hausregel, an der schon zwei Live-Defekte hingen). Der `ControlStatusListener` verwirft ein unbekanntes Wort, statt es zu speichern, und **`NULL` heißt „unbekannt", NIE „nicht zertifiziert"** — wer die zwei zusammenfallen lässt, schickt einen Kunden zu einem Prüfstand, den er nicht braucht. Spalten additiv auf `device_control_status`, Felder additiv auf `ControlStatusDto`.
- **Endpunkte** (`AdminControlCertificationController`, klassenweit `@PreAuthorize("hasRole('platform-admin')")`, Repository an der BYPASSRLS-Rolle `voltpilot_admin` — die `/admin/fleet`-Disziplin): `GET/POST/DELETE /api/v1/admin/control-certifications`, `GET /api/v1/admin/control-activations`, `GET /api/v1/admin/control-candidates` (jede Anlage samt gemeldetem Urteil), `POST/DELETE /api/v1/admin/devices/{id}/control-activation`. In `openapi.yaml`.
- **WER klicken darf: platform-admin, und nur der** (Design-Entscheidung mit Begründung, nicht Bequemlichkeit): das Register ist eine Produkt-Zusage der Plattform; es geht um SCHREIBZUGRIFF auf den Wechselrichter eines Kunden, den der Kunde nie hatte; und eine spätere Kunden-Freigabe ist additiv nachrüstbar (eine zweite Route auf dem RLS-Pfad, wie `SiteFlowController` neben `AdminFlowController`), das Umgekehrte wäre es nicht.
- **Erstbestand:** die Deye-Freigabe des Captains (`sun-30k-sg01hp3` / `hybrid_3p` / Pfad `remote`) wird von der Migration eingetragen — genau das „merken", das die Order verlangt. Sie ändert an keiner laufenden Anlage etwas: ohne Scharfschaltung steuert sie nichts, und die Pilsting-Box behält ihren lokalen Grant unabhängig davon.
- **⚠ `onDeviceUnclaimed` löscht die Aktivierungs-ZEILE ABSICHTLICH nicht — sie stirbt am FK-CASCADE (im Testcontainers-Lauf als echte SELBST-BLOCKADE reproduziert).** `DeviceController.unclaim` ist `@Transactional` auf dem `@Primary` (mandantenbezogenen) Datenpfad und hat die Gerätezeile schon gelöscht, hält also bis zum Commit die Sperre auf den kaskadierenden Zeilen — ein `DELETE` von der BYPASSRLS-Verbindung aus wartet dann auf einen Commit, der ohne seinen eigenen Rücklauf nie kommt (Thread hing im Postgres-Zeilenlock, `jstack` zeigte `ControlCertificationRepository.deactivate`). Das ist die Kehrseite derselben Regel, aus der in `RolloutService` kein `@Transactional` steht: **die zwei Datenpfade dürfen sich nie gegenseitig belauern**, und `rollout`s Aufräumen funktioniert nur, weil `device_update_target` KEINEN FK auf `device` hat. Aufgeräumt wird deshalb hier ausschließlich der retained Slot (Broker, keine DB).
- **Sicherheits-Leitplanken unverändert:** globaler Not-Aus (`VP_CONTROL_ENABLED`), `guards.Clamp` (Nennband, SoC-Fenster, §14a, EEG-Solarklemme), Magnitudenkappung und jede Layer-1-Regel binden wörtlich weiter. Ein unzertifiziertes Modell wird durch nichts hiervon steuerbar; ein Ausfall des Registers ist fail-closed (kein Dokument = keine Plattform-Freigabe).
- **Beweise:** rein `internal/controlcert` (18: Modell-vs-Familie, Vorzeichen-Widerspruch, unbekannt≠nicht-gedeckt, fail-closed, die Kontrakt-Fixtures PER PFAD) · `agent/controlcert_test.go` (10: der Kernfall „neue Box ohne lokalen Beweis", beide Halbwahrheiten, fremde Identität, **die Plattform nimmt einer Box NIE ihren lokalen Grant**, ohne Dokument keine Datei, Neustart, Herzschlag) · api `ControlCertificationPublisherTest` (Draht-Form, NULL wird weggelassen) + `ControlStatusListenerTest` (Ingest + Dreiwertigkeit + unbekanntes Wort verworfen) + Testcontainers `ControlCertificationApiTest` (echtes EMQX: Erstbestand im Register, EIN Klick → retained Dokument, zweites Modell erreicht dieselbe Box ohne Zutun, Doppel-Eintrag 409, Rücknahme sofort, Unclaim leert den Slot, Rollen-Grenze) · portal `controlCertification.test.ts` (15) + die drei Situationen in `control.test.ts`.
