# Ersparnis-Simulation (Inkrement 1, design `vp-sim-design-t6`)

Ausgelagert aus `AGENTS.md` am 05.09.2026 (Abschnitt Nr. 109).


The operator what-if instrument (captain framing 2026-07-16: an instrument, not a hard-sell tool): 3 scenarios over the last FULL calendar year - (a) ohne Speicher / (b) Standard-Speicher / (c) VoltPilot - plus a battery-size sweep and the Netzladen variant, computed with the UNCHANGED production solver against the real prices + real Open-Meteo-ARCHIVE weather of that year. Headline = "Speicher + VoltPilot gegenüber ohne Speicher" (a−c net), the 3-way breakdown fully visible, the Netzladen potential one calm sign-honest line. V1 is STATELESS: no prospect data persisted, results live ~1 h in the job cache (repeat inputs are answered instantly via a normalized-input SHA-256 cache).

- **`simulation` compose service = the optimization IMAGE with `command: ["simulate-serve"]`** (the weather-collector pattern - no new image, no CI matrix change; dev under the `optimize` profile, prod with `cpus: "3.0"` + `SIM_MAX_WORKERS` so the 15-min production optimizer never starves). Internal-only stdlib HTTP (`voltpilot_optimization/simulation/server.py`: `POST /simulations` 202/400/429, `GET /simulations/{id}`, `/health`); it knows NEITHER tenants NOR tokens - ALL auth lives in the api (ingest JdbcDeviceDirectory trust pattern). One job at a time + queue depth 4 → 429 with German copy.
- **Method facts are load-bearing (measured in the design report - do not "optimize" them away):** scenario (c) chains 365 days with a **48-h window committing 24 h** (naive 24h/24h chaining reproduces the §4.3 horizon artefact 365×, measured −148 €/a vs. greedy); month chunks parallelize with **2 warmup days** solved-and-discarded (measured −0,03 % vs. the sequential gold chain; the January chunk starts at the SoC floor with no warmup, byte-identical to sequential); **day sampling is forbidden** (−8..−55 % bias - midnight cuts the overnight carry); the year end looks ahead into a CYCLIC wrap (Jan 1 follows Dec 31). Greedy (b) = report §5 exactly: same physics (capacity/power/√η-split/SoC band incl. backup reserve, start at floor), zero intelligence, never grid-charges, wear charged POST-HOC at the same preset ct so "netto" is one currency; the measured pointe is that greedy cycles MORE. Pricing/EEG/wear logic exists ONCE - the runner calls `pricing.import_prices`/`export_values` and `solver.optimize` unchanged; the Netzladen variant re-prices export at merchant terms (bare spot) and reports `zusatzVorteilNettoEur` (negative for many EEG households - the Vergütung entfällt - shown honestly).
- **Load profile:** synthetic household (`simulation/profiles.py`, double hump + weekend/season modulation, scaled EXACTLY to the Jahresverbrauch). **BDEW H25 is NOT bundled - license verified NOT clearly permitted** (bdew.de Impressum: downloads private/non-commercial only, redistribution needs written consent; demandlib bundles it with the OPEN license issue oemof/oemof-demand#22). The adapter exists behind `SIM_BDEW_H25_JSON` (operator-provided file, never redistributed); the repo ships the **`bdew-convert` CLI** (`simulation/bdew_convert.py`, `[convert]` extra = openpyxl) that turns the operator's OWN download of the official publication into that JSON - expansion semantics (SA/FT/WT day types incl. Feiertage-as-FT + Dec-24/31-as-SA, the VDEW-H0 Dynamisierung for H25/P25/S25, wall-clock slot indexing across DST, leap years, 1-Mio-kWh normalization check) documented in the module, operator note in `services/optimization/README.md`; bundling the DATA still needs the captain's written BDEW permission. NOTE the adapter's slot index is WALL-CLOCK (`(day_of_year-1)*96 + quarter`, profiles.py's same-tzinfo subtraction is naive) - the converter deliberately matches it.
- **Price backfill prerequisite:** `day_ahead_prices` only grows forward, so run once per reference year+zone (idempotent upsert, quarter-sized keyless energy-charts calls): `python -m voltpilot_market_data backfill --year 2025 --persist` (compose: `docker compose run --rm market-data backfill ...`). The sim service is DB-only + deterministic afterwards; a missing/gappy year fails the job with a German message naming this command (gaps ≤ 3 h are filled with the last price).
- **api orchestration (`simulation/` package + `web/SimulationController`/`AdminSimulationController`):** customer `POST/GET /api/v1/sites/{siteId}/simulation[/{id}]` (tenant-scoped like every site route; defaults resolved from master data via `SimulationDefaultsRepository` - tariff/plant kind/anzulegender Wert/coords/battery asset incl. RAW wear ct + PV asset - body fields OVERRIDE, Speicherschonung preset mapped via the ONE `web/Speicherschonung` constant; missing coords/battery → German 400) and admin `POST/GET /api/v1/admin/simulation[/{id}]` (platform-admin, explicit inputs, X-Tenant-Id NOT needed). The proxy relays the service's German 400/429 verbatim (`SimulationClient`; transport failure → 502) and `SimulationJobRegistry` (in-memory, TTL) scopes polls: a site job is only readable through ITS site route, an admin job only through the admin route - an api restart forgets jobs → 404 → the portal restarts (cache makes it instant). Test seam = `ObjectProvider<SimulationHttp>` (the MastrHttp pattern), proven by `SimulationApiTest`.
- **Portal:** customer subpage `#/anlage/{id}/simulation` (Mehr-card on the Anlagen-Seite; prefilled what-if form, 2-s poll with progress bar + progressively filling months, 3 scenario cards, headline sentence, Netzladen line, monthly chart, Beispieltag dispatch chart Standard-vs-VoltPilot, Größen-Sweep-Kurve with base-size marker + marginal-value sentence, mandatory footnote) and the Plattform page "Ersparnis-Rechner" (`pages/admin/ErsparnisRechnerPage.tsx`, `LocationSearch` instead of a site). ALL wording/derivation is the pure `src/simulation.ts` (`simulation.test.ts`); shared render in `components/SimulationView.tsx`.
- **Tests:** optimization `tests/test_simulation.py` (profiles/greedy vectors/price expansion+gap policy/archive parse+cache/request validation), `test_simulation_runner.py` (real HiGHS over a SHRUNK monkeypatched year: chunked == sequential gold, parallel == sequential, MILP ≥ greedy, scenario-(a) exactness, result-document shape, Netzladen variant), `test_simulation_server.py` (job round trip, 400/404/429, cache, progressive results); market-data `tests/test_backfill.py`; api `SimulationApiTest`; portal `simulation.test.ts`.
- **The chunk pool MUST use the SPAWN start method (real CI wedge 2026-07-16, job 2587 >2.5 h):** `run_milp_year`'s `ProcessPoolExecutor` forks on Linux by default, and forking after HiGHS/OpenMP threads exist livelocks the children at 100 % CPU on an inherited barrier (reproduced in a 2-CPU container; macOS never shows it - spawn is its default). The pool now passes `mp_context=get_context("spawn")`, bounds workers by chunks + usable CPUs (`effective_workers`, serial below 2), and the suite carries `pytest-timeout` (`timeout = 300` in pyproject) so any future wedge FAILS loudly. Heavy year-chain tests are `@pytest.mark.slow` - the CI gate runs `pytest -m "not slow"` (deploy.yaml passes `matrix.pytest_args`; a 3-day chaining smoke stays in the default set), plain local `pytest` runs everything; all deploy.yaml/deploy-fast/edge-images jobs carry `timeout-minutes` so a wedge can never block the single runner for hours. Convention documented in `services/optimization/README.md` "Test markers / CI selection".
