# Edge `:8484` web app: TWO pages (Betrieb / Einrichten) + Technikmodus

Ausgelagert aus `AGENTS.md` am 05.09.2026 (Abschnitt Nr. 104).


**Structure (concept `data/vp-edge-ux-concept/concept.html`, owner-approved 2026-07-27, branch `fm/vp-edge-ux-overhaul-h6`).** The device page has exactly two jobs: **`index.html` = Betrieb** (status line, Energiefluss, Kennzahlen, Verlauf, Fahrplan, Steuerungs-ZUSTAND - customer-grade, no buttons) and **`einrichten.html` = Einrichten** (a four-step guided commissioning flow ending at "Daten kommen an", then the areas: Wechselrichter/Erzeuger/Zähler, Portal-Kopplung, Steuerung freigeben, Messwert-Aufbereitung, Unumkehrbar). `inverter.html`/`einstellungen.html` survive ONLY as redirects into an area anchor - old URLs must never 404. A single **Technikmodus** switch (`technik.js`, same header position on both pages, `localStorage`, default OFF) reveals inline technical depth; it is NOT a gate. THE rule it encodes: **hidden content must never hide a CAUSE** - every non-ok verdict of the pure `status.js`/`control.js`/`commissioning.js` derivations carries a plain-German `cause` rendered in NORMAL mode. Details + the per-file map: `edge-app/AGENTS.md` "The `:8484` web app: TWO pages + Technikmodus".

**"Meine Anlage" (now the first AREA of Einrichten)** is one card with three ROLE groups instead of the old always-open form + flat source list: **Wechselrichter / Speicher** (`inverter.js`: a summary row with a live status dot/pill + a "Bearbeiten" toggle that reveals the model-picker form; the form is NOT permanently rendered), **Erzeuger** (N) and **Netz-Zähler** (0–1) (`sources.js`: `renderGroups()` partitions `/api/sources` by role). Adding a source opens a **drawer** (`.drawer`, side panel → full-screen sheet under `@media (max-width:640px)`) with a two-card **role picker** (`.role-pick`, replaces the old `<select id="srcRole">`; the Netz card is `disabled`/`locked` once one exists, so the 0–1 limit is visible before submit). Status pills use `shell.css` `.pill.ok/.warn/.off` (NOT the portal React `Badge`); `verify.js` (`window.VP`) holds the shared status-pill mapping + the "Verbindung testen" handler, reused by both scripts. Source rows are delete-only (no edit endpoint exists). The Go page-structure test `web_test.go TestInverterPageServesModelPickerStructure` pins the ids (`anlageCard`/`invGroup`/`erzList`/`netzList`/`srcDrawerBackdrop`/`rolePick`/`invVerify`/`srcVerify`/`invTestBtn`/`srcTestBtn`) on `einrichten.html`. The despike buttons are `#despikeSaveBtn`/`#despikeResetBtn` - the inverter form owns `#saveBtn` now that both live on one page. **`static/*` is `//go:embed`-ed — rebuild the core binary after editing** (any `go build`/`go test ./internal/web` re-embeds).

- **Per-source live status (`GET /api/sources`).** The response now carries a `statuses` map (source id → `"ok"|"warn"|"pending"`) alongside `sources`+`catalog`, so the page renders the status dot without a second call. `agent.SourceStatuses()` surfaces the existing freshness machinery (`srcReadings`/`sourceFresh`): `ok` = fresh reading, `warn` = had a reading but now stale, `pending` = none yet (never a fabricated status). Additive edge-local state, no cloud/contract change. The inverter row's status derives from `/api/state` `inverter_connected`.
- **`POST /api/test-connection` ("Verbindung testen") — a bounded local-bus round-trip, NEVER a save gate.** The web app posts the UNSAVED connection form (same brand/model/connection shape as the inverter/source save, `testconn.Request`); `agent.TestConnection` normalizes it against the catalog, publishes it non-retained on **`edge/test-read/request`** with a `request_id`, waits ~10 s on **`edge/test-read/result`** (correlated by id, `testReadTimeout` var), and returns `testconn.Result` (`ok`+`reading{pv_kw?,load_kw?,grid_kw?,soc_pct?}` or a classified `error_code`: `unreachable|no_answer|invalid_response|implausible|fronius_api|invalid_request|timeout`). Contract twin of `edge/control/readback`; `localbus.go` documents both topics. Node-RED side: two vp-palette nodes **`vp-test-request`** (subscribe) + **`vp-test-result`** (publish), and a **"Verbindung testen" flow tab** whose function node reads the device ONCE via **`test-read.js`** (`makeReadOnce(deps)` — the canonical, unit-tested source of truth orchestrating route + one-shot socket/HTTP read + decode + classification, reusing `deye-decode`/`modbus-tcp`/`fronius(solar-api)`/`solarman-v5`). `build-flows.js` EMBEDS `test-read.js` + those four self-contained decode modules verbatim into the flow node (a flow cannot `require`), and `flows-sync.test.js` pins the embed against the files. Tests: Go `agent/testconn_test.go` (correlation/timeout/classification passthrough vs a fake bus) + `web` endpoint tests; Node `test-read.test.js` (all classifications + modbus/fronius reads vs in-process servers), `test-read.flow.test.js` (the embedded flow node vs an in-process modbus server), `vp-palette` node tests. **Reuse-scope note:** to get the 5 distinct error states, the test-read path does its OWN non-idle-safe reads (the self-wiring poll's readers swallow errors to idle); it embeds the decode modules rather than reusing the poll's reader nodes.
