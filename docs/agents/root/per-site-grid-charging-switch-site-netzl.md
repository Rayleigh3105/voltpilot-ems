# Per-site grid-charging switch (`site.netzladen_erlaubt`, EEG compliance)

Ausgelagert aus `AGENTS.md` am 05.09.2026 (Abschnitt Nr. 67).


Captain decisions 2026-07-07 (binding: firstmate `vp-grid-charging-modes`): EEG-funded plants must never charge their battery from the grid (Ausschliesslichkeitsprinzip), so grid arbitrage is an ADMIN-gated opt-in per site.
One api migration **`V20260707000000`** adds `site.netzladen_erlaubt BOOLEAN NOT NULL DEFAULT FALSE` - every existing plant stays compliant until explicitly switched.

- **One optimizer, TWO conditional constraints (captain decisions: switch 2026-07-07, FK3 2026-07-16, EN-2 A 2026-11-02).** `inputs.py` reads the flag per site; when FALSE, `solver.py` adds (in the primary AND the infeasible-§14a fallback build) `charge_t <= max(pv_t, 0) - curtail_t` (`solar_only_charge`, FK3) and `import_t <= M_imp_t·(1 − is_charging_t)` (`strenge_ausschliesslichkeit`, ported from MiSpeL MP-45, no tolerance): a slot that charges imports nothing, so the battery charges only from the forecast PV SURPLUS. FK3 alone let the house import its load in parallel while the PV bus charged ("DC-hybrid physics"); at the grid connection point that is grid power in the storage - the BNetzA reading since its MiSpeL determination of 2026-10-01 - and Herzogau charged 25,6 kWh that way on 2026-11-02 ("das darf nie wieder passieren"). Do not turn it back. Subtracting `curtail` stays load-bearing (a fully curtailed slot cannot charge). Curtailment itself stays available to EEG sites (it limits feed-in, not charge availability). The v2 co-optimizer carries both rules in `modules.SolarOnlyChargeModule` per storage without grid-charge permission (golden suite equal). Proof: `services/optimization/tests/test_mispel_strenge.py` (incl. the Herzogau 02.11. pattern: house 6,5 kW, PV 1–3 kW → no charge). Merchant mode (`true`) builds the byte-identical pre-switch model - the untouched arbitrage tests + `test_eeg_constraint_exists_only_in_eeg_mode_and_in_both_builds` pin the regression. `OptimizationInput.netzladen_erlaubt` is REQUIRED (no default) so a forgotten wire-up can never silently put an EEG plant into arbitrage.
- **Editing: the SITE OWNER may switch it too (captain REVISION of decision 3, 2026-07-07 midday, screenshot feedback - the original decision was ADMIN-ONLY).** `CreateSiteRequest`/`UpdateSiteRequest` carry a nullable `netzladenErlaubt` that any caller may set on the sites they reach - RLS already scopes that to the caller's own tenant, so no extra role gate remains (`SiteController.requireAdminForNetzladen` is REMOVED); admins keep working via the tenant switcher and the admin create path. Null on update keeps the stored value (`COALESCE` in `SiteRepository.update`), so a form that omits the field never flips the flag; the DB default stays FALSE. On `SiteDto`/`OverviewSiteDto` + `openapi.yaml`. Proven by `AdminApiTest.netzladenSwitchIsEditableByTheSiteOwnerAndAdmins` (customer sets on create + flips both ways on update of their OWN site; omitted field = default FALSE on create / stored value on update; a FOREIGN tenant's site stays RLS-404 and provably unchanged; admin create + tenant-switcher flip keep working; overview echoes the flag).
