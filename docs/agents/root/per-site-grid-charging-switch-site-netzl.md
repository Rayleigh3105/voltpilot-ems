# Per-site grid-charging switch (`site.netzladen_erlaubt`, EEG compliance)

Ausgelagert aus `AGENTS.md` am 05.09.2026 (Abschnitt Nr. 67).


Captain decisions 2026-07-07 (binding: firstmate `vp-grid-charging-modes`): EEG-funded plants must never charge their battery from the grid (Ausschliesslichkeitsprinzip), so grid arbitrage is an ADMIN-gated opt-in per site.
One api migration **`V20260707000000`** adds `site.netzladen_erlaubt BOOLEAN NOT NULL DEFAULT FALSE` - every existing plant stays compliant until explicitly switched.

- **One optimizer, ONE conditional constraint - PV-bus Bilanzierung since FK3 (captain decisions: switch 2026-07-07, semantics 2026-07-16, audit `vp-solver-xlsx-f2` §4.6).** `inputs.py` reads the flag per site; when FALSE, `solver.py` adds (in the primary AND the infeasible-§14a fallback build) `charge_t <= max(pv_t, 0) - curtail_t`: the battery may charge up to the full PV actually PRODUCED **while the house imports its load in parallel** (DC-hybrid physics, "wie meine Excel" - the pre-FK3 Zähler interpretation `charge <= max(pv − load, 0)` plus an import-ban-while-charging was strictly tighter and forbade charging on cloudy days the reference spec allows). Subtracting `curtail` is load-bearing: it replaces the removed import ban as the CURTAILMENT-loophole closure - a fully curtailed slot cannot charge, and via the grid balance a charging slot's import never exceeds the load, so grid energy can never enter the battery (Graustrom excluded, the pricing layer's premium-eligibility argument preserved). Curtailment itself stays available to EEG sites (it limits feed-in, not charge availability). Merchant mode (`true`) builds the byte-identical pre-switch model - the untouched arbitrage tests + `test_eeg_constraint_exists_only_in_eeg_mode_and_in_both_builds` pin the regression. `OptimizationInput.netzladen_erlaubt` is REQUIRED (no default) so a forgotten wire-up can never silently put an EEG plant into arbitrage.
- **Editing: the SITE OWNER may switch it too (captain REVISION of decision 3, 2026-07-07 midday, screenshot feedback - the original decision was ADMIN-ONLY).** `CreateSiteRequest`/`UpdateSiteRequest` carry a nullable `netzladenErlaubt` that any caller may set on the sites they reach - RLS already scopes that to the caller's own tenant, so no extra role gate remains (`SiteController.requireAdminForNetzladen` is REMOVED); admins keep working via the tenant switcher and the admin create path. Null on update keeps the stored value (`COALESCE` in `SiteRepository.update`), so a form that omits the field never flips the flag; the DB default stays FALSE. On `SiteDto`/`OverviewSiteDto` + `openapi.yaml`. Proven by `AdminApiTest.netzladenSwitchIsEditableByTheSiteOwnerAndAdmins` (customer sets on create + flips both ways on update of their OWN site; omitted field = default FALSE on create / stored value on update; a FOREIGN tenant's site stays RLS-404 and provably unchanged; admin create + tenant-switcher flip keep working; overview echoes the flag).
- **Portal visibility (captain decision 4 + the decision-3 revision):** the shared `NetzladenBadge` component ("Nur Solarladen (EEG)" green / "Netzladen aktiv" cyan; wording in `fleet.ts netzladenBadge`) on the fleet site card + the Standort detail drawer; the "Netzladen des Speichers" select renders for EVERYONE in `SiteEditForm`/`CreateSiteDrawer` (the former `isAdmin`/`admin` gating props are gone) with the Ausschliesslichkeitsprinzip warning copy carrying the responsibility ("Nur aktivieren, wenn Ihre Anlage keine EEG-Vergütung bezieht"); the old read-only "Änderung nur durch den Betreiber (Portal-Admin)" note is retired.
