# v2 entity model - pilot minimum (E1a)

Ausgelagert aus `AGENTS.md` am 05.09.2026 (Abschnitt Nr. 45).


The first RUNTIME slice of the EMS-v2 track (contracts: `docs/contracts/v2/`, decisions D-1..D-14): exactly the three pilot entity types - **battery-hybrid, producer (PV), grid-meter** - end to end. A device without a pushed registry (and a site without bootstrapped entities) behaves byte-for-byte v1; coexistence is dual-CONSUME cloud-side, never dual-publish on old devices.

- **Contracts authored by E1a** (the topic homes E0 reserved): `mqtt-telemetry-2.0` (per-entity numeric channels on `ems/{t}/{s}/{d}/v2/telemetry`, envelope-only cloud validation), `edge-entity` (the D-3 family's config/telemetry/command shapes + the retained registry push on `…/v2/entities`; guard limits + failsafe live IN REGISTRY CONFIG per D-9, `charge_from_grid_allowed` absent = NOT allowed per D-8), and the `telemetry-v2.raw` Kafka event. Fixture discipline: >=2 valid + 1 invalid per schema in `examples/`; the RUNTIME validators are the executable contract checks (ingest `TelemetryV2ValidatorTest`, Go `internal/entities` tests - both read the fixture FILES from `docs/contracts/v2/examples`, so moving them breaks tests deliberately).
- **Cloud registry** = `measurement_point` + `entity_type`/`capabilities`/`guard_config` (api migration `V20260718000000`, additive - every v1 constraint intact; the DROPs for multi-battery are E1b). A row with non-NULL `entity_type` IS a v2 entity. NOTHING converts automatically: the **pilot bootstrap** `POST /api/v1/admin/sites/{siteId}/v2-entities/bootstrap` (platform-admin via the X-Tenant-Id switcher, RLS path, `entities/EntityRegistryService`) composes the three entities from the site's existing master data (battery asset -> battery-hybrid incl. the control measurement_point row; pv-generation points -> producer; grid-meter -> grid-meter) - idempotent, used later by the E13a cutover. The registry is pushed as ONE retained message on `…/v2/entities` (`EntityRegistryPublisher`, best-effort, rides `voltpilot.provisioning.*`); gateway device = the battery's controlling device else the site's single device, never a guess. The battery-hybrid row is platform-managed: hidden from the portal sources panel and 409-guarded against the v1 customer delete.
- **Telemetry v2 pipe (dual-consume):** ingest's SECOND Paho adapter on `ems/+/+/+/v2/telemetry` (`VOLTPILOT_TELEMETRY_V2_ENABLED`, default on; the 5-segment v1 filter never matches the 6-segment v2 topic) envelope-validates and produces `telemetry-v2.raw` (keyed `{tenant}:{site}`); the writer's v2 listener explodes events into the generic `(entity_id, channel, value)` hypertable **`telemetry_v2`** (api migration `V20260718010000`: RLS like telemetry, unique `(entity_id, channel, time)` idempotency, per-entity ts override, `received_at` = arrival for liveness, v1 purge watermark honored) + a minimal per-entity 15m rollup with its own background job. The v1 path is byte-identical untouched; portal read paths over telemetry_v2 are later work.
- **Go edge entity layer** (`internal/entities` pure model + `agent/entities.go` wiring): the cloud link subscribes the retained registry push (empty payload clears); the agent persists it (`entities.json`), mirrors per-entity RETAINED `edge/entities/{id}/config` on the local bus (boot republish - in-process retained state dies with the process), consumes `edge/entities/+/telemetry` (identity rule; unknown entities ignored) and forwards readings LIVE as 2.0 uplink (no v2 store-and-forward yet - E1b). **Per-entity guards from registry config** (the D-9 generalization of env-derived `guards.Limits`): capability gate first, then battery-hybrid through `guards.Clamp` with the registry band/SoC window/D-8 posture, producer reduce-only nameplate caps, grid-meter drops everything. The v1 execution path's clamped setpoint is MIRRORED onto the battery-hybrid entity's retained `…/command` re-clamped through the entity chain (most-restrictive-wins) - so per-entity guards are live before E2's arbitration (desired/arbitration deliberately stubbed). Heartbeat gains the additive `entities` ack block (revision/count/ids). **Footgun fixed once already: `entUplink`/`entReadings` must be initialized in `New()`** - a nil channel in a select/default silently drops every uplink sample.
- **ACL (D-2):** every per-device grant block carries TWO extra wildcard lines (publish + subscribe `ems/{t}/{s}/{d}/v2/#`) covering all current and future v2 topics. E14 consolidation has NOT landed, so the template lives in BOTH emitters - `AclGrantWriter.grantBlock` and `voltpilot-ca.sh write_acl_grant` - byte-identically; the SAME fixed vector is pinned in `AclGrantWriterTest` and `tools/pki/test-acl-grants.sh` (change both together; `merge-acl-grants.sh` moves blocks verbatim and needs no change). Startup `regenerateGrants` upgrades enrolled devices' blocks to the new shape on deploy; shell-provisioned v1 grants keep the old shape until re-issued (harmless - v1 devices never touch v2 topics).
