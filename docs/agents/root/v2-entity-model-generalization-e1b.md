# v2 entity model - generalization (E1b)

Ausgelagert aus `AGENTS.md` am 05.09.2026 (Abschnitt Nr. 46).


Everything E1a deferred, on the proven pilot base: arbitrary entity types, the v1 single-battery constraint drops, bidirectional Soll/Ist sync, full per-entity rollups + history, the portal entity surface, and v2 uplink buffering. A registry-less device still behaves byte-for-byte v1. HA-Bridge is CANCELLED (native drivers only, plan D3); no HA mapping surface anywhere.

- **Open entity_type vocabulary.** `edge-entity.schema.json` `entity_type` is now an OPEN kebab-case pattern (`^[a-z][a-z0-9-]{0,62}$`), NOT an enum. The **data-driven type CATALOG** `services/api/src/main/resources/entitytypes/catalog.json` (loaded by `entities/EntityTypeCatalog`, served at `GET /api/v1/admin/entity-type-catalog`) is the truth for known types - the pilots plus consumer types **wallbox / heating-rod / generic-load**; **adding a type is catalog data + an optional edge driver (E6), never a schema release, never a DB migration**. Consumers key BEHAVIOR on declared capabilities/guards, never the type string. Catalog fields: `category` (storage|producer|meter|consumer - steers the edge guard semantics), `controllable` (may carry `control=TRUE`), `composed` (config derived from v1 master data - not directly creatable/guard-editable), `default_measure/_actuate/_failsafe`. `guard_limits` gained the additive `max_consumption_kw` (consumer rated cap; consumers only ever commanded to CONSUME, setpoint ≥ 0, V2G out of scope).
- **Go edge (`internal/entities`).** `ParseRegistryPush` ACCEPTS unknown well-formed types (skips only MALFORMED); guard semantics are CATEGORY-inferred (`Entity.category()`): pilots pinned, else storage-shaped guards → the full battery chain incl. D-8, `max_generation_kw` → producer reduce-only, no-actuate/measure-only-failsafe → drop-everything, otherwise the consumer clamp `[0, min(capability max, max_consumption_kw)]` + on_off + declared-mode validation. `entities_test.go` reads the new consumer fixtures.
- **Constraint drops (migration `V20260719010000`, v1 behavior PRESERVED).** Drops the `measurement_point` pilot-type CHECK + control-only-battery CHECK + one-control-per-site partial unique (consumer entities ARE control points, a site may have several; control safety moved to the catalog-driven service). Reworks `asset UNIQUE(site_id,type)` → a **primary-scoped partial unique** `uq_asset_site_type_primary WHERE is_primary` + an `is_primary BOOLEAN DEFAULT TRUE` column; **ALL v1 asset readers/upserts carry `AND is_primary` in LOCKSTEP** (`AssetRepository` ON CONFLICT + wear/link/pv-capacity, `OptimizerConfigRepository`, `ScheduleRepository`, `SimulationDefaultsRepository`, `OptimizerDiagnosticsRepository`, `EntityRegistryRepository.batteryAsset`, optimizer `inputs.py`, forecast `forecast_collect.py`) - change all together. A second non-primary battery is now representable at the registry level; multi-storage asset composition is E4/E6 follow-up.
- **Full per-entity rollups + history (migration `V20260719020000`).** Extends the E1a 15m rollup to the 15m/1h/1d cascade (Europe/Berlin daily, sample-weighted `avg(avg*n)/Σn`; the `telemetry_v2_rollups_job` procedure body is replaced, the job unchanged; one-time backfill). `repo/EntityHistoryRepository` + `web/EntityController` serve `GET /api/v1/sites/{siteId}/entities/{entityId}/history?range=day|week|month|year` (day=raw / week=1h / month+year=1d, the v1 `HistoryRange` discipline), RLS-scoped.
- **Bidirectional Soll/Ist sync (migration `V20260719030000`).** Cloud stays Soll; the edge reports its Ist in the heartbeat `entities` block (per-entity `observed` {type, health ok|stale|never, last_telemetry_at, channels} + `local_setup` = the edge-authoritative `:8484` inverter/sources view). `entities/EntityStatusListener` (the `ControlStatusListener` pattern, flag `VOLTPILOT_ENTITIES_MQTT_LISTENER_ENABLED`, on in both composes) ingests it into `entity_observed_state` (RLS, replaced wholesale per heartbeat); `EntityRegistryService` records the composed Soll revision into `entity_registry_state`. `GET /api/v1/sites/{siteId}/entities` reconciles them into a per-entity `syncStatus` (in_sync | pending | missing_on_device | unreported | never_pushed) + `staleOnDevice` - drift is SURFACED, never silently overwritten in either direction.
- **v2 uplink store-and-forward.** The v2 entity telemetry uplink rides the SAME `internal/buffer` as v1 (E1a was live-only): `buffer.Entry` gained an optional `entity_id` discriminator (old JSONL stays v1, no on-disk migration), `AppendEntity` enters readings with their ORIGINAL ts, the one `publisherLoop` drains both eras confirm-then-ack (`PublishTelemetryV2(buffer.Entry)`), the purge watermark + unclaim-pause apply verbatim. The E1a live-only uplink loop is retired.
- **Admin CRUD + portal surface.** `AdminEntityRegistryController` POST/PUT/DELETE `/v2-entities[/{id}]` create/edit/delete open catalog types incl. guard config (composed pilot types refused 422; unknown type 400; garbage guards 400). Portal Anlage subpage `#/anlage/{id}/entitaeten` (`pages/EntitaetenSection.tsx`): read-only per-entity cards (type, capabilities, live health, guard config) + Soll/Ist drift banner + the edge-local commissioning view for everyone; admins get create/edit/delete via a Drawer driven by the type catalog. All copy/verdicts are the pure unit-tested `src/entities.ts`; `api.ts` `siteEntities`/`entityHistory` reads, `src/entitiesApi.ts` admin writes.
