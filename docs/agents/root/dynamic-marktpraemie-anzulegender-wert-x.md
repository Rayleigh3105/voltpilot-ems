# Dynamic Marktprämie (anzulegender Wert x Monatsmarktwert Solar) + Marktwert-Benchmark

Ausgelagert aus `AGENTS.md` am 05.09.2026 (Abschnitt Nr. 69).


Captain domain fix 2026-07-07 (task vp-marktpraemie-dynamisch): the EEG premium is NOT a fixed ct/kWh - fixed is the plant's **anzulegender Wert** (its EEG reference rate); the premium per exported kWh in month M is `max(0, anzulegender_wert - monatsmarktwert_solar(M))`, suspended in negative-price slots (the simplified §51 rule kept), credited on BOTH earnings sides exactly like before.

- **Field:** `site.anzulegender_wert_ct_kwh` (api migration **`V20260707020000`**, nullable NUMERIC >= 0). The old `site.marktpraemie_ct_kwh` is DEPRECATED, not migrated (a fixed premium and a reference rate are different quantities; the column shipped one day earlier, so meaningful prod values are unlikely but unverifiable from the sandbox - hence keep-one-release, echoed read-only on `SiteDto`, dropped from Create/Update requests, `deprecated: true` in `openapi.yaml`; a follow-up migration removes it). Forms (`CreateSiteDrawer`, `AnlageTechnik` `SiteEditForm`) now say "Anzulegender Wert (ct/kWh)" with the help "Steht in Ihrem EEG-Zuschlag bzw. Direktvermarktungsvertrag", DV-only as before.
- **Monatsmarktwert-Solar feed (`services/market-data`):** new `market_value.py` (port `MarketValueSource` + `MonthlyMarketValue` + the provisional calc) and `netztransparenz.py` - a **KEYLESS** adapter against the endpoint feeding netztransparenz.de's own Marktwertübersicht chart (`POST /DesktopModules/LotesCharts/Services/HighchartService.asmx/GetMarketpremiumData`, plain JSON, verified live 2026-07-07, data back to 2012; the OFFICIAL WebAPI needs a registered OAuth2 client, so it is NOT keyless - documented upgrade path if the chart endpoint ever moves; energy-charts has no market-value endpoint). The `MW Solar` column is located BY NAME, never position. Table **`monthly_market_value`** (service migration `V20260707001000`; api `V20260707020000` is the idempotent runtime twin + app-role SELECT grant; mirrors in `infra/local/timescale/05-market-value.sql` + `infra/prod/timescale/00-collector-tables.sql`): market-wide, NO tenant/RLS, deliberately NOT a hypertable (twelve rows/technology/year); PK `(technology, month)`, `month` = first day of the GERMAN calendar month, `provisional` flag. The `serve --persist` loop refreshes it every cycle (previous + current year), and `market-values [--persist]` is the one-shot CLI; upsert rule: published always overwrites, provisional NEVER overwrites published.
- **Provisional value (months the TSOs have not published yet - always the running month, usually also the previous one until ~the 10th working day): the OFFICIAL formula, not an approximation (upgraded 2026-08-05).** `provisional_solar_market_value` applies **Anlage 1 Nr. 2.2 EEG 2023**, `MW(M) = Σ(p_i·E_i)/Σ(E_i)`: the stored DE-LU day-ahead prices weighted by the Germany-wide solar generation of the same quarter hours. **The quantity `E` is a keyless fallback chain** (`solar_generation.py` port + `FallbackSolarGenerationSource`): (1) the **ÜNB Online-Hochrechnung der tatsächlichen Erzeugung** (`netztransparenz_generation.py` - the SAME ASMX service as the market-value adapter, `GetChartData` with `dataType=4`/`productId=42145141`, quarter-hourly MW per TSO summed over the four control areas; `dateFromCet`/`dateToCet` are GERMAN WALL CLOCK, so one request = one calendar month) - this is the quantity the EEG names; (2) energy-charts `public_power?country=de` (`EnergyChartsSolarGenerationSource`, `Solar` production type located BY NAME) as substitute; (3) only if neither answers, the weather-blind clear-sky shape `clear_sky_weighted_solar_market_value` (`max(0, sin(solar elevation))` over 51.16N 10.45E - the pre-2026-08 behaviour, kept as documented last resort); (4) nothing weighted => `None`, never a fabricated value. **Measured against the official June 2026 value of 6.190 ct/kWh: ÜNB 6.1897 (−0.0003), energy-charts 6.372, clear-sky 6.966, unweighted average 10.952** - so the source RANKING is load-bearing, not cosmetic; `MarketValueRefreshResult.provisional_weighting` reports which quantity actually weighted each month. **Join rule:** a generation sample belongs to the price slot containing its MIDPOINT, and a slot's weight is the SUM of its samples' ENERGY (`power_mw × hours`) - so a legacy hourly price slot meeting four quarter-hourly samples gets its correct four-fold share. **The generation series is fetched per refresh cycle, never persisted** (consumed immediately, no other reader - a hypertable would be pure overhead). Two honesty rules in the parser/calc: an empty TSO cell (newest, not-yet-computed interval) is SKIPPED, never read as zero; and a part-month value is a running average that CONVERGES as the month fills up - it is neither a month value nor a forecast, and nothing models the remaining days (deliberately out of scope). The row STAYS `provisional` (the Online-Hochrechnung is itself revised, and tenth-of-a-cent deviations remain) until the official value overwrites it. No stored prices for a month => NO row => no premium (never invented). **Checked live 2026-08-05 and NOT available: netztransparenz publishes no intra-month provisional Monatsmarktwert endpoint** (its Marktwertübersicht carries published months only), so our own weighting is the primary path, not a diagnostic cross-check.
- **Earnings (`EarningsRepository`):** `MARKET_VALUE_JOIN` maps each rollup bucket's Europe/Berlin month to `monthly_market_value` ('solar'); `PREMIUM_RATE_CT = GREATEST(anzulegender_wert - mv.value, 0)`; eligibility additionally requires a market-value row. NULL anzulegender Wert OR missing month => exactly the pure-spot numbers (regression-pinned). The **benchmark KPI** rides the same aggregate: `realizedExportCtKwh` (export-weighted spot the feed-in fetched, EUR/MWh / 10), `marketValueSolarCtKwh` (Monatsmarktwert weighted with the SAME exports - like-for-like across months), `marketValueProvisional` (bool_or over contributing months) - null without exports/coverage, never fake zeros; separate denominators so a missing month degrades the benchmark, not the realized number.

Marktprämie: anzulegender Wert X ct − Monatsmarktwert Solar Y ct (vorläufig), entfällt bei negativen Preisen"; `marktwertBenchmark()` renders the calm KPI line "Sie haben X,X ct/kWh für Ihren eingespeisten Strom erzielt − Monatsdurchschnitt Solar: Y,Y ct" in the site-scoped `EarningsHero` (Anlagen-Seite; the fleet hero keeps generic wording - mixed reference rates never average).
