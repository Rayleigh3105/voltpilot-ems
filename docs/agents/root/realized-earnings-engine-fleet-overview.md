- **The math per 15-min slot and site** (`EarningsRepository`, ASYMMETRIC since Stufe 3 of the structured Bezugspreis - report vp-nacht-bezug-e7 §3.4): the baseline (UNREGULATED plant: same generation/consumption, battery idle) is SPLIT per slot - `baseline_import = GREATEST(load−pv, 0)` valued at the site's real IMPORT PRICE, `baseline_export = GREATEST(pv−load, 0)` at the EXPORT VALUE (spot + premium, or the feste EEG-Vergütung - next bullet); actual = metered import × import price − metered export × export value. The import price is the ONE composition truth **`SlotEconomics.importPriceCtSql`** - the SQL twin of `importPriceCtKwh`/pricing.py `import_prices`, generated in the SAME class (fest = flat retail; dynamisch/ohne + maintained `site_supply_price` sheet = `(spot + Σ Komponenten) × (1+USt)`; dynamisch + Aufschlag; else bare spot, or the researched default set behind the mirrored `OPTIMIZER_DEFAULT_SUPPLY_COMPONENTS` flag) - so display and steering tell the same math; `HistoryRepository` consumes the same fragment. Equivalence is pinned vector-for-vector against real Postgres by `PortalApiTest.importPriceSqlMatchesTheSlotEconomicsCompositionVectors` (flag on AND off), endpoint vectors + the bare-`ohne`-stays-byte-identical rollout rule by `savedEurValuesAvoidedImportAtTheStructuredSupplyPrice`. Both sides are signed COSTS (negative = revenue); round-trip losses still debit VoltPilot. HISTORIK-SEMANTIK (documented v1 simplification): every slot is valued at the CURRENTLY maintained tariff/Preisblatt - no price-sheet history. The `arbitrageSplit` attribution deliberately stays spot-valued (documented in its Javadoc; the remainder construction keeps `arbitrage + pvShift == saved` exact). `EarningsSiteDto.tarifPriced` + `HistoryTotalsDto.tarifPriced` tell surfaces whether the number is tariff-valued ("bewertet zu Ihrem Stromtarif") or bare spot.
- **The EXPORT side is the ONE composition too (audit vp-geldzahlen-audit-x7 B2, fixed 2026-09-01).** Every export term (Einspeise-Erlös, the metered export inside `actualEur`, the residual export inside `baselineEur`) applies **`SlotEconomics.exportValueCtSql`** - the SQL twin of `exportValueCtKwh`/pricing.py `export_values`, its feste-Vergütung band schedule generated by **`EegRates.festeVerguetungCtSql`** from the SAME `OPTIMIZER_EEG_RATES_JSON`-aware band list (tranche blending by kWp, 20-year expiry at the SLOT's Berlin year, §51a zeroing at negative spot for plants commissioned ≥ 2025-02-25). Before the fix an EEG-vergütete `eigenverbrauch` plant saw bare spot - incl. negative "Erlöse" a fixed remuneration never has. The rate needs the site's PRIMARY `pv` asset (`commissioned_on` + `pv_capacity_kwp` - the `LEFT JOIN asset pv … is_primary` in every money query); **no commissioned pv asset = honest bare-spot fallback, never a guessed rate**, and DV plants stay byte-identical (spot + Marktprämie). Because ONE per-slot rate values metered AND residual export, `saved == baseline − actual` and `strom − einspeise == actual` stay exact identities. ⚠ **ONE documented deviation from the Java twin:** the SQL keeps crediting the Marktprämie to a `netzladen_erlaubt` DV site (today's earnings behavior), while `exportValueCtKwh`'s netzladen-first guard strips it - pinned BY NAME in the lockstep test. `exportVerguetungPriced` (`EarningsSiteDto`/`SiteEarningsDto`, the `tarifPriced` sibling) tells the portal the export was valued at the feste Vergütung; the Portal-Anzeige dafür ist bewusst NICHT gebaut (läuft im Redesign). `realizedExportCtKwh` stays deliberately spot (a market BENCHMARK, not a revenue statement). Proofs: `PortalApiTest.exportValueSqlMatchesTheSlotEconomicsCompositionVectors` (Java ≡ SQL vector-for-vector against real Postgres, incl. the pinned deviation) + `eegFixedRemunerationValuesTheExportSideAndKeepsTheIdentitiesExact` (hand-computed EEG plants incl. a §51a negative-price slot, identities exact, the honest fallback, fleet twin parity).
