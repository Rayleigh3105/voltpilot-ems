# Forward expected Marktwert Solar (`GET /api/v1/earnings` `expectedMarketValueSolarCtKwh`)

Ausgelagert aus `AGENTS.md` am 05.09.2026 (Abschnitt Nr. 71).


Captain decision 2026-07-09 (`vp-expected-marktwert-solar`): a per-Anlage, FORWARD-looking market value - what the market values THIS plant's coming production, weighted by its own PV forecast. The forward companion to the realized/backward `marketValueSolarCtKwh`. Additive, no data-model change.

- **The calc (`EarningsRepository.expectedMarketValue(pvModel, now)`):** `Σ(price(t) × pv_forecast(t)) / Σ(pv_forecast(t))` over the forward slots where BOTH a day-ahead price AND this site's PV forecast exist, then EUR/MWh `/10` -> **ct/kWh** (same unit as `marketValueSolarCtKwh`). Data sources REUSED, not rebuilt: `day_ahead_prices` (same `PRICE_LATERAL` slot match as the realized aggregates, joined per the site's OWN `bidding_zone`, PT15M preferred over PT60M) and the `forecast` hypertable (`kind='pv'`, LATEST `run_at` of the **ACTIVE** PV model only - shadow challengers ignored, same rule as the optimizer's `inputs.py`; the api reads the active model from `voltpilot.forecast.active-pv-model`). The forecast is POWER (`forecast.value_kw`, kW); the constant 15-min slot length cancels in the weighted average, so weighting by power == weighting by energy. Negative-price slots are INCLUDED (they legitimately pull the value down); zero-production night slots contribute 0 to both sums and never distort the weighting.
- **RLS:** `forecast` carries NO RLS (backend-only consumers), so the query JOINs the RLS-scoped `site` table to fence it to the caller's tenant - the same technique the realized aggregates use (no tenant predicate). `now` is `Instant.now()`; the figure is RANGE-INDEPENDENT (always the coming horizon), computed once per request regardless of `range`.
- **DTO:** `EarningsSiteDto.expectedMarketValueSolarCtKwh` + `expectedMarketValueFrom`/`...To` (covered forward-slot bounds) + `expectedMarketValueSlots` (count, so the portal can say "nächste N h"). ALL FOUR null (site absent from the repo map -> controller emits nulls) when there is no forward PV forecast or no forward price coverage (Σ(pv)=0 -> value NULL -> row dropped) - never a fabricated 0. In `docs/contracts/openapi.yaml`.
- **Portal:** one calm line under the money hero, see `frontend/portal/AGENTS.md` ("Forward Erwarteter Marktwert Solar"). Derivation in `src/anlage.ts` `expectedMarketValueLine`.
- **Tests:** `PortalApiTest.earningsExposeTheForwardExpectedMarketValueWeightedByPvForecast` (forward-seeded relative to `now()` so it exercises the real `time >= now()` filter: three CH slots 100/200/-40 EUR/MWh weighted 2/6/1 kW -> `1360/9/10` ct/kWh, a priced zero-PV night slot that widens the horizon but not the value, a shadow-challenger row that must be ignored, a forecast-but-no-price site -> null, range-independence, RLS); portal `anlage.test.ts`.
