# Multi-source Anlage (Phase 1): N Erzeuger per site, aggregated ON THE EDGE

Ausgelagert aus `AGENTS.md` am 05.09.2026 (Abschnitt Nr. 103).


The fix for the general "AC-coupled PV invisible -> garbage load (46,7 kW)" bug: a site with a **battery-hybrid inverter PLUS a separate AC-coupled PV** was measured wrong because the edge read only the one inverter, so the hybrid's balance misattributed the second PV's ~70 kW to load. Phase 1 lets a site have **N additional read-only Erzeuger (PV) measurement points** and **sums them into ONE composite site reading on the EDGE**, so the existing single `edge/telemetry` contract stays byte-for-byte unchanged downstream (ingest/rollups/portal/earnings/optimizer untouched - the rollups `avg()` per site, which is exactly why aggregation must NOT happen in the cloud). Design: `data/vp-multisource-edge-design/report.md` §3/§4 (the Luxone role-tagged measurement-point tree; Phase 1 = the **Erzeuger** role, then **Increment 1** adds the **Netz** grid-meter role — see the Increment 1 subsection below; Verbraucher/Wallbox still deferred). Captain decisions 2026-07-09.

- **Edge core aggregation (`edge-app/core/internal/sources` + `agent`).** `sources.Source` reuses the inverter `Catalog` (brand/model/family/communication/connection) + `role`/`capacity_kwp`/`registry_unit_id`/`interval_s`; persisted `sources.json` (like `inverter.json`) and re-published **retained** on the NEW local-bus topic `edge/sources/config` (`sources.BusConfig`). A source is **READ-ONLY BY CONSTRUCTION** (no control field/topic ever). Additional sources publish per-source telemetry on `edge/sources/{id}/telemetry`; the agent subscribes the wildcard, keeps the latest PV per source with a freshness window (`max(3*interval, 60s)` - **error isolation: a dead/stale source is ABSENT, never a fabricated 0**), and at the existing `onLocalTelemetry` choke point sets `site_pv = primary_pv + Σ fresh Erzeuger` BEFORE the guards run; the house then follows the **captain-decreed standard (2026-07-17)** `house = pv_total + grid − battery` (see the house-consumption-standard note in edge-app/AGENTS.md) - the old `max(0, load - Σ Erzeuger)` netting estimate survives only on the raw-load fallback path (no usable site grid, or an unknown-family primary without a measured battery). **Zero sources = byte-for-byte the single-source path** (empty cache, no publishers on the wildcard). The physical envelope PV bound widens to Σ generation nameplate (`guards.EnvelopePvBound`; primary rating + Σ `capacity_kwp`), battery bound stays the primary's. Web API `GET/POST/DELETE /api/sources` (`web.SourcesController`; add form reuses `GET /api/inverter` catalog). The `:8484` inverter page gained a "Weitere Energiequellen" list+form (`static/sources.js`; `//go:embed` - rebuild core after edits). Tests: `internal/sources` + `agent/source_agg_test.go` (two-source sum + load correction, absent/stale isolation, zero-source byte-for-byte, envelope widen/narrow) + `web`.
- **Node-RED read fan-out (`edge-app/nodered`).** `vp-sources-config` palette node (subscribe retained `edge/sources/config`, emit the array -> `flow.sources_config`) + `vp-quelle` node (publish one source reading on `edge/sources/{id}/telemetry`, topic-injection-guarded). `sources-routing.js` (`parseSourcesConfig`/`planSources`, reusing `inverter-routing.route`). `build-flows.js` "Energiequellen (automatisch)" tab: sources-config -> store (modbus read plans) -> poll -> **sequential** per-source Modbus read (error-isolated) -> vp-quelle; `flows.json` regenerated (idempotent), `flows-sync.test.js` pins the inlined store + SunSpec PV decode. **SCOPE (E6, all read transports wired): the flow executor reads EVERY read transport in EVERY source slot** - `modbus_tcp` (the compact sim profile the e2e uses), `fronius_sunspec` via the embedded SunSpec-live discovery walk (`sunspec/model-discovery.js` + `sunspec/sunspec-live.js`), `goe_http_api` (a go-e wallbox Consumer), `solarman_v5` (a Deye over its Solarman-V5 logger - `readSolarmanReading` embeds `deye/solarman-v5.js` + `deye/deye-decode.js`) and `fronius_solar_api` (a Fronius over its Solar API v1 - `readFroniusReading` embeds `fronius/solar-api.js`). The store validates the Deye family + logger serial and the Go `sources.busEntry()` forwards each transport's connection fields (solarman serial/scale, fronius insecure_tls/invert_grid_sign, SunSpec unit/model_type). Publish per role: Erzeuger -> `pv_power_kw`, Netz -> signed `power_kw`, Consumer -> `load_kw`; sequential (never two sockets to one device), error-isolated (a dead source -> absent, never a fabricated 0). The whole class of "recognised by routing but plan silently dropped" (the 2026-07-13 `sunspec_live` device-down) is now closed for the remaining transports. Proven by `sources-read.e2e.test.js` (in-process SunSpec/Solarman-V5/HTTP servers: Erzeuger publishes `pv_power_kw`, Netz publishes signed `power_kw`, Consumer publishes `load_kw`, dead source error-isolated + warned).
- **Data model (`services/api` + portal).** `asset(site_id, type)` STAYS the AGGREGATE PV/battery the optimizer + earnings read; the PV asset's kWp becomes **primary + Σ additional Erzeuger** (`AssetRepository.addPvCapacity` applies exact per-op deltas on create/delete so it never clobbers a MaStR/manual primary kWp). New **`measurement_point`** child table (api migration `V20260709000000`, RLS-scoped like `asset`): role vocabulary (Phase 1 `'pv-generation'`), per-source `capacity_kwp` + `registry_unit_id` (the source's OWN MaStR SEE #, optional - captured, never blocks adding), nullable `device_id` (additional points need NO device row/cert/claim - read through the one claimed edge). **Control safety enforced in the DB:** a CHECK forbids `control=true` on any non-`battery-hybrid` role, and a partial unique index allows AT MOST ONE control point per site. `MeasurementPointController` `GET/POST/DELETE /api/v1/sites/{id}/measurement-points` (RLS 404 foreign, non-Erzeuger 400). Portal: the Technik "Mein Gerät" card's `ErzeugerSourcesPanel` records sources (master data only, no second claim; fails soft). `openapi.yaml` + `PortalApiTest` (aggregate = Σ, delete drops it, RLS/400/404, the DB CHECK + one-control constraints) + portal `ErzeugerSourcesPanel.test.tsx`.
- **Deferred (noted precisely):** syncing the portal `measurement_point` master data down to the edge `sources.json` (today the edge `:8484` UI and the portal record sources independently); the edge's live source list + per-point health now DOES reach the portal (see Increment 2 above, #524); per-source telemetry visibility in the cloud (would need the rollups to sum-per-point). ### Increment 2 (partial): the per-source PV breakdown reaches the portal (#524)

The 2026-07-21 PV incident's real fix: the portal showed only the COMPOSITE PV, so a multi-inverter site read "39 kW" with no way to see it is Deye 8,3 + Fronius 21,3 + Fronius WR 2 9,3 - verifying meant opening the edge's `:8484`. The edge-reported per-point list now reaches the portal. Pure added VISIBILITY: the composite telemetry/aggregate path is byte-for-byte untouched, and it rides the STATUS channel, never telemetry.

- **Edge → cloud:** the additive `sources` block on the status heartbeat (`cloud.SourcesSummary`/`SourceEntry`, built by `agent.sourcesSummary()` in `internal/agent/entities.go`, capped at 16 entries): the primary inverter (its OWN pv from `Snapshot.LastReading`, captured BEFORE the multi-source fold - never the composite) plus every configured source from the existing `SourceStatuses`/`SourceLastReadings` freshness machinery. `health` is `ok|stale|never`; an absent measurement stays absent. A site with nothing configured emits NO block; a single-inverter site emits a list of one. Proof: `agent/sources_summary_test.go`.
- **Cloud:** `SourceStatusListener` (`services/api` `sources/`, flag `VOLTPILOT_SOURCES_MQTT_LISTENER_ENABLED`, on in both composes) is the third sibling on `ems/+/+/+/status` next to the control/entity listeners - same authorization posture (broker ACL + mTLS-CN, topic==payload identity re-validated, device resolved through the RLS repository under the topic tenant) - and REPLACES the device's whole set wholesale in `device_source_status` (migration `V20260721000000`, RLS like `device_control_status`), because the heartbeat carries the COMPLETE Ist. Served by `GET /api/v1/sites/{siteId}/sources` (RLS-fenced, foreign site 404, admins via the X-Tenant-Id switcher; empty list = no device reported the block yet). Proof: `PortalApiTest.siteSourcesExposeThePartsOfTheCompositePvTenantScoped`.
- **Portal:** the live view (`pages/LiveSection.tsx`, both the v1 `LiveHero` and the adaptive branch) renders `components/PvBreakdown.tsx` under the PV figure, driven by the pure `src/pvSources.ts` (`pvBreakdown`/`breakdownLine`/`sourceLabel`/`healthTitle`; `pvSources.test.ts`). It shows ONLY with 2+ measuring devices (a single-inverter site is byte-identical to before), the shown parts always sum to what they say, a producer without a reading is NAMED in a note instead of counted as 0, and a stale part keeps its last value with a grey dot. Fetch is fail-soft - an older edge/backend simply yields no breakdown.
- **Still deferred:** per-source TELEMETRY (history/rollups per point) in the cloud, and syncing the portal `measurement_point` master data down to the edge `sources.json`.

### Increment 1: Netz-Zähler (grid meter) — edge-configured, edge-aggregated, grid-authoritative

The money-relevant correctness slice on the SAME edge-authoritative pattern (report `data/vp-ms-replan-k4/report.md` Increment 1, captain-approved 2026-07-09): a dedicated grid meter at the point of common coupling makes `site_grid` an authoritative **measurement** instead of the primary hybrid inverter's CT (grid import/export drives earnings + the optimizer). **Zero cloud change, NO migration** — a meter's value simply *becomes* `power_kw`. `measurement_point.role` already reserved `'grid-meter'`.

- **Edge core** (`internal/sources` + `internal/agent`): `sources.RoleNetz = "grid-meter"` joins `RoleErzeuger`; `Normalize` accepts both (a meter needs no `capacity_kwp`, same `Catalog` transport validation). `agent.sourceReading` carries `pv *float64` AND `grid *float64` (signed, +import/-export); `onSourceTelemetry` parses `power_kw` alongside `pv_power_kw` (either absent per role). At the `onLocalTelemetry` fold, AFTER the Erzeuger PV sum, `authoritativeGrid()` (mirrors `aggregateSourcePv`, same freshness window) overrides `measurements["power_kw"]` with the newest FRESH Netz reading; a stale/absent meter falls back to the primary CT (graceful degradation, never fabricated). The grid override lands in the cloud buffer + history ring (the state snapshot has NO grid field — assert via `hist.Recent`). `applyEnvelope` sums ONLY `RoleErzeuger` kWp, so a Netz meter adds nothing to the PV bound; the history ring's battery line is the measured register (2026-07-17 standard), so the meter's `power_kw` feeds the house balance, not a battery derivation. Zero Netz sources = byte-for-byte the pre-Increment-1 path.
- **Node-RED**: `vp-netz` palette node (grid twin of `vp-quelle`, forwards signed `power_kw`, same topic-injection guard). `sources-routing.planSources` keeps `ROLE_ERZEUGER || ROLE_NETZ` and carries `role` in the plan. `build-flows.js` "Energiequellen" tab: the sequential read decodes by role — Erzeuger → `pv_power_kw` (SunSpec reg 1) to `vp-quelle` (output 1), Netz → signed `power_kw` (SunSpec reg 0) to `vp-netz` (output 2); `flows.json` regenerated, `flows-sync.test.js` pins both inline decodes.
- **Edge `:8484` form** (`static/sources.js` + `einrichten.html`): a role picker (Erzeuger / Netz-Zähler); the Netz path hides the kWp + MaStR fields. The web `SourcesController` is role-generic (validation is in `Normalize`), so no backend change there.
- **api** (master data only): `MeasurementPointController` accepts `grid-meter`, SKIPS `addPvCapacity` for it, and enforces **0–1 Netz per site** (`MeasurementPointRepository.countByRole`; a second → 409). It ALSO accepts `consumer` (E6, 2026-07-20): no `capacity_kwp` requirement, NO `addPvCapacity` effect, NO per-site count limit (a site may have several); the DB CHECK (control only on battery-hybrid) is untouched since a source is `control=FALSE`. `openapi.yaml` updated; the portal `ErzeugerSourcesPanel` gained an "Art der Energiequelle" picker (PV-Erzeuger / Verbraucher).
- **Tests**: Go `source_agg_test.go` (fresh Netz overrides / stale falls back / no-Netz no-op / envelope unchanged) + `sources_test.go` (Normalize accepts Netz, rejects unknown) + `web_test.go` (Netz add 200, unknown role 400); Node `vp-netz` shaping + routing + flows-sync; api `PortalApiTest` (Netz accepted, no PV bump, second Netz 409, unknown role 400).
