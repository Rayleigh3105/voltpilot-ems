# Secure MQTT broker (real remote-device onboarding, mTLS)

Ausgelagert aus `AGENTS.md` am 05.09.2026 (Abschnitt Nr. 36).


The path for a physical Node-RED edge to reach a **self-hosted** broker over the internet and publish contract telemetry. Full model in [`docs/security-mqtt.md`](docs/security-mqtt.md); device-facing guide in [`docs/connect-a-device.md`](docs/connect-a-device.md). The dev experience is **unchanged** - the hardened broker lives in the production compose (`docker-compose.prod.yml`), not the dev `docker-compose.yml`, so the base EMQX block is untouched.

- **Two listeners.** Plaintext `1883` stays for local dev + the internal ingest consumer. A hardened **mTLS `8883`** listener (`verify_peer` + `fail_if_no_peer_cert`) is defined by the production compose `docker-compose.prod.yml` (server cert + device CA mounted from `infra/mqtt/certs/`, git-ignored). Devices make an **outbound-only** connection (architecture §6 - no inbound edge ports).
- **Identity binding.** Device cert subject `O={tenant_id}, OU={site_id}, CN={device_id}` (+ SPIFFE SAN). CN carries `device_id` (UUID fits the 64-char CN limit; the full `tenant/site/device` path does **not**, which is why it is NOT crammed into one CN). The broker sets `peer_cert_as_username=cn` / `peer_cert_as_clientid=cn` (in EMQX 5.x a GLOBAL `mqtt.*` setting, env `EMQX_MQTT__PEER_CERT_AS_*` - the listener-scoped env form is rejected as `unknown_env_vars`; verified on 5.8.3, harmless for cert-less 1883 clients), so a device can't spoof its identity.
- **Per-tenant/-device ACL** in `infra/mqtt/acl/acl.conf` (EMQX file authorizer, first-match): internal `vp-internal` user gets full `ems/#` (ingest); each device gets a **generated grant** allowing only its own `ems/{t}/{s}/{d}/telemetry|status` (up) and `…/schedule|command|config` (down); any UUID username without a grant is **default-denied everything** (that is how revocation works). Cross-tenant publish is denied. The `acl/` DIRECTORY (never the file) is bind-mounted into EMQX (ro) and the api (rw): the api's grant writer replaces `acl.conf` atomically via rename, which fails with EBUSY when the target is a single-file mountpoint - and a single-file mount would pin the broker to the replaced inode anyway (both verified live; this was a real prod outage). **`acl.conf` must stay world-readable (0644)**: EMQX reads it as a different non-root uid, and both grant writers' temp files (`mktemp` / `Files.createTempFile`) are born 0600 - the rename carries that mode onto the file, a running broker keeps its compiled rules, and the breakage only surfaces at the next authz reload/restart as a boot-time validation failure (`failed_to_read_acl_file: Permission denied`; also a real prod outage). Both writers now force 0644 on every write path, and the deploy workflows `chmod 755` the dir + `chmod 644` the file after the ACL merge as belt-and-braces. Grant changes apply via `tools/pki/reload-broker-authz.sh` - **`emqx ctl conf reload` does NOT re-read the file** (the file authorizer compiles rules at source init and only re-initializes on a config change; verified on 5.8.3 - the script forces the re-init through `emqx eval 'emqx_authz:update({replace, file}, ...)'`); the CI deploy workflows run it after `up -d`, and they MERGE the deployed ACL's generated grant region via `tools/pki/merge-acl-grants.sh` instead of overwriting it (runtime grants would otherwise be revoked on every deploy).
- **Grant ORDERING is load-bearing + self-healing (prod-down 2026-07-08, PR fm/vp-acl-grant-order-fix).** First-match means a device grant is only reachable if it sits ABOVE the catch-all UUID default-deny, i.e. INSIDE the `%%<<BEGIN..>>..%%<<END GENERATED DEVICE GRANTS>>` region. The captain's real device (`cdba2ee8`) was claimed with its grant written BELOW the deny + `{allow, all}` and the whole template tail DUPLICATED, so it was unreachable → denied → kicked off the broker → reconnect loop → no telemetry → "offline" in the portal (the dev-seed `…0003` grant sat correctly in-region, which is why sim/demo worked). Every grant writer now does a full CANONICALIZING rebuild on each write (collect all device blocks wherever they sit, insert/replace this one, re-emit exactly ONE region above exactly ONE collapsed tail) so any claim/unclaim SELF-HEALS a corrupted file: `AclGrantWriter` (Java, primary, `services/api/.../enrollment`), `voltpilot-ca.sh` `normalize_acl` (portable awk - field-2 id, NO gawk 3-arg `match()`), and `merge-acl-grants.sh` (collects grants from ANYWHERE in the deployed file - an out-of-region grant is no longer silently dropped). **Deploy alone repairs it with NO manual edit and NO re-claim:** `EnrollmentService.selfHealBrokerAclOnStartup` (`@PostConstruct`) runs `AclGrantWriter.normalizeInPlace()` on api boot - rewrites ONLY when something changed (a healthy file is left byte-identical, no reload noise; missing anchors → SKIPPED, never a crashed boot), logs the RESOLVED `acl.conf` path (so a wrong mount is obvious in deploy logs) + a loud WARN naming what it fixed. **The reload is the load-bearing half and now runs SYNCHRONOUSLY at startup with the outcome checked** (hardening PR `fm/vp-acl-selfheal-e2e`, 2026-07-08): after a heal the api calls `BrokerAuthzReloader.reloadNowBlocking(3, 2s)` (bounded retries for a rolling-deploy blip; `reloadNow()` now returns a boolean) and, if EMQX did NOT accept the reload (broker unreachable / misconfigured / feature off → `getIfAvailable()` null), logs a loud, ACTIONABLE **ERROR** naming the break-glass (`tools/pki/reload-broker-authz.sh` or `docker restart emqx`) instead of silently leaving the device denied. Issuance/unclaim still use the async coalesced `requestReload()`; only startup is synchronous. **With `broker-authz-reload` enabled (prod compose sets it), NO `docker restart emqx` is needed** - the REST `PUT /authorization/sources/file` makes the RUNNING broker re-read; a plain `emqx ctl conf reload` does NOT (verified 5.8.3). **End-to-end PROVEN against a real EMQX 5.8.3 by `AclSelfHealBrokerE2eTest`** (Testcontainers, named `*Test` so surefire runs it, `disabledWithoutDocker`): boots EMQX with the captain's exact corrupted shape (seed grant in-region + `cdba2ee8`-style grant BELOW the deny + duplicated tail, `no_match=deny`/`deny_action=ignore`), a real MQTT SUBSCRIBE to the device's schedule topic is DENIED (SUBACK 0x80) while the in-region seed device is allowed, then `normalizeInPlace()` + `reloadNowBlocking()` (the two steps the `@PostConstruct` runs) flip the SAME device to ALLOWED on the running broker - the missing link the prior text-only tests never covered. The captain's live VM was hand-fixed once; this prevents recurrence. Tests: `AclGrantWriterTest` (ordering, corrupted-shape heal, idempotency, committed-file no-op, startup heal, regenerate-from-truth) + `AclSelfHealBrokerE2eTest` (real-EMQX deny→heal+reload→allow) + `tools/pki/test-acl-grants.sh` (29 assertions, offline, runs under bwk/mawk/gawk).
  - **AMENDMENT (residual prod-down 2026-07-08, PR `fm/vp-acl-always-reload`): REGENERATE grants from the DB source of truth on boot + ALWAYS reload.** Two gaps bit again: (1) the captain's device grant was **ENTIRELY MISSING** from the live `acl.conf` (an EARLIER buggy rebuild had DROPPED it, not just misordered it) - you cannot reorder or reload a grant that is not in the file; and (2) the startup reload fired **only when `normalizeInPlace` changed the file**, so a long-running EMQX (up 26h+ across the deploy) holding STALE compiled rules over an already-canonical file was NEVER reconciled → deploying #100/#101 didn't fix it because the reload never fired. **The definitive fix:** `selfHealBrokerAclOnStartup` now (a) REBUILDS the generated-grant region from what the api KNOWS - `AclGrantWriter.regenerateGrants(devices.allEnrolledDeviceIdentities())`, a new method emitting a correct in-region grant for EVERY claimed+enrolled device (`EnrollmentDeviceLookup.allEnrolledDeviceIdentities()` = `device_enrollment` JOIN `device` WHERE `cert_pem IS NOT NULL`, BYPASSRLS admin datasource) so a **dropped grant is RESTORED**, a misordered one fixed, duplicate tails collapsed, and grants NOT in the DB list (shell-provisioned via `tools/pki`) are PRESERVED (union of file + DB truth, never a truth-only replace that would revoke them); DB unreachable at boot → falls back to canonicalize-only (fixes ordering, still reloads), never crashes the boot; a file with no region anchors → SKIPPED (a fully-wiped file the DB alone can't reconstruct, and the only case that short-circuits the reload). Then (b) it **ALWAYS** calls `reloadNowBlocking(3, 2s)` - REGARDLESS of whether the file changed - so every api start/restart reconciles EMQX's live ruleset with the current file. `normalizeInPlace()` is kept (pure canonicalize, still unit-tested); `regenerateGrants` is its superset. **Deploy OR restart the api → every enrolled device's grant is reconstructed from the DB and EMQX re-reads it, zero manual steps.** Proven end-to-end vs real EMQX 5.8.3 by **`AclRegenerateReloadBrokerE2eTest`** (two independent containers: a MISSING grant regenerated-from-truth flips the device to ALLOWED; an already-canonical file over a STALE broker still reloads-and-flips despite NO file change) + `EnrollmentServiceStartupReloadTest` (wiring: regenerate+always-reload, DB-down fallback, skip-when-no-anchors, never-crash) + `AclGrantWriterTest` (regenerate restores a missing grant, never drops a grant sitting after a 2nd END marker, preserves shell grants, unchanged when complete) + `EnrollmentApiTest.enrolledDeviceIdentitiesListDrivesTheStartupAclRegeneration` (real DB: claimed+enrolled in the list, CSR-only/unclaimed excluded).
- **CA + issuance tool** `tools/pki/voltpilot-ca.sh` (openssl, `openssl.cnf`): `init-ca` (CA once + broker server cert), `issue --tenant --site --device` (client cert + ACL grant), `revoke --device` (CRL + grant removal), `gen-crl`, `list`. Keys land in `tools/pki/out/` (git-ignored) - **never committed**.
- **Provisioning** `tools/pki/provision-device.sh` ties it together: calls the portal `POST /api/v1/devices/claim` (reusing device-claiming, tenant from the JWT `tenant_id` claim), then issues the cert bound to the returned `device_id`, and prints connection params.
- **Run it:** `docker compose -f docker-compose.prod.yml up -d` (the standalone production stack, which includes the hardened broker) after `init-ca` + staging `infra/mqtt/certs/`. Only `8883` is public (1883/dashboard → loopback); firewall is the real guarantee (hardening checklist in `docs/security-mqtt.md`). Full deploy flow: `docs/deploy.md`.
- **Verify (Docker-free):** `python3 tools/pki/verify_mqtt_security.py` - runs a real mutual-TLS handshake (valid cert connects, no/untrusted cert rejected, revoked cert fails CRL) and evaluates the real `acl.conf` with EMQX first-match semantics (own-path allow, cross-tenant deny, down-only enforcement, internal allow). This sandbox blocks Docker, so the live EMQX-on-18883 + mosquitto recipe is documented (not executed) in `docs/security-mqtt.md`.
