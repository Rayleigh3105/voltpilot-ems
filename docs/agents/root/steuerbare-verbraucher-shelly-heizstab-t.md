- **Der CORE besitzt den GANZEN Shelly-Socket** (`edge-app/core/internal/shelly` + `agent/shelly_control.go`): Quellen-Poll, D11-Verbindungstest UND Executor - anders als bei go-e gibt es KEINEN Node-RED-Lesepfad (der Dialekt ist zustandsbehaftet; `sources.BusConfig` schließt Shelly-Quellen aus der retained Node-RED-Config aus). Beide **Generations-Dialekte werden ERKANNT, nie konfiguriert** (`GET /shelly`: `gen`≥2 = RPC-Dialekt Gen2/3/4, `type` ohne `gen` = Gen1-REST) und persistiert (`shelly-devices.json`); Passwortschutz wird ehrlich abgelehnt (v1 ohne Auth).
- **D3-Messfähigkeit ist ein GERÄTE-Fakt** (Gen2: `apower` vorhanden; Gen1: `meters[ch].is_valid`, VERIFY-on-device): ein messender Shelly (1PM/Plug-S) publiziert die gemessene Leistung als Entity-Telemetrie → Erfüllungs-Ledger **Stufe 2** (INTEGRATED); ohne Messung NIE ein Leistungswert (Quellen-Reading trägt nur das reale Faktum `relay_on`) → **Stufe 3** "angenommen" (Nennleistung × Zeit). **Die Capability-Kette bis ins Anlegen:** `device_source_status.load_kw IS NOT NULL` = nachgewiesene Messung → `ConsumerService.create` leitet beim Quellen-Bind `consumer_profile.confirmation_channel` ab (`power_kw`/`relay_state`; ungebunden NULL = nie "erfüllt") → `ConsumerDto.confirmationChannel` → die Ink1-Regel (kWh-Ziele nur mit Messung) keyt im Portal darauf (`consumerHasMeasurement`, Typ-Heuristik als Fallback - unbekannt ist nie "nein"); der Assistent zeigt je gemeldeter Quelle "misst Leistung" / "ohne Leistungsmessung (Energie wird angenommen)".
- **Failsafe `off` + ON-DEVICE-Totmann:** jeder EIN-Befehl trägt den geräteeigenen Abfall-Timer (Gen2 `toggle_after`, Gen1 `timer`; 180 s = 3× der 60-s-Re-Assert, der ihn neu stempelt) - Edge tot/WLAN weg ⇒ das Relais fällt VON SELBST ab (aufhören zu schreiben IST der Failsafe); Staleness schreibt zusätzlich aktiv AUS (§4.2 - bewusst nicht das go-e-Neutral). Restrict-only: ein Sub-Nennleistungs-Sollwert schaltet NICHT ein. Zyklen-Guard/Klemme binden unverändert vorgelagert.
