# Fahrplan-Warum backend (per-slot "why" facts: optimizer explain layer + schedule columns)

Ausgelagert aus `AGENTS.md` am 05.09.2026 (Abschnitt Nr. 79).


The optimizer computes + persists the honest per-slot decision facts of every plan (design scout `vp-fahrplan-why-design`, owner-approved D1-D6; the portal rendering is a separate later PR). **`voltpilot_optimization/explain.py`** runs AFTER `_extract_plan` on the still-live model: fix every binary to its MILP value AND relax its domain to `Reals` (BOTH required - `.fix()` alone leaves APPSI/HiGHS treating it as a MIP with no duals), fresh APPSI `Highs()` LP re-solve (~30-40 ms/cycle, objective drift <= 1e-13), then read the duals with the empirically verified sign conventions: **`λ_t = −dual(soc_dynamics[t])`** (value of a stored kWh at slot END, the "Wasserwert" - the EXACT number `SlotEconomics` previously approximated), **`π_t = dual(grid_balance[t])/dt`** (effective energy value at the connection point), **`μ_t = −dual(peak_epigraph[t]) − dual(peak_below_epigraph[t])`** (Leistungspreis allocation; Σ over slots+anchor = LP exactly, Σ ratchet duals = ratchet). Binding flags come from a primal-slack/bounds scan (no duals needed); the slot role is the §6 precedence rule-tree (`abregeln`/`reserve_halten`/`warten`/`pv_speichern`/`guenstig_laden`/`spitze_kappen`/`verkaufen`/`eigenverbrauch`), deadbands = the shared `schedule.ts`/`SlotEconomics` constants (third copy in explain.py - change together).

- **Safety invariants (non-negotiable):** the committed plan is BYTE-IDENTICAL with explain on/off (proven per golden scenario); the LP re-solve MUTATES the model so it runs strictly after plan extraction and its solution is never loaded back (`load_solution=False`, no `load_vars()`); ANY explain exception (incl. a garbage flag value) warn-logs and ships the plan with all why-fields None - explain can never sink a plan; flag `OPTIMIZER_EXPLAIN_ENABLED` (default true) is the instant off-switch; the why NEVER reaches MQTT (publisher builds payloads field-by-field). The Ersparnis-Simulation passes `optimize(..., explain_plan=False)` (365 solves/job would pay ~11 s for discarded fields).
- **Maintenance coupling (§11.6):** whoever adds a model constraint MUST extend `explain.KNOWN_CONSTRAINTS` + the binding scan/role tree - `explain()` REFUSES unmapped constraints (plan then ships why-less), and `test_explain.py`'s inventory guard fails at dev time.
- **Data contract (§5.1, api migration `V20260723030000` + mirror `infra/local/timescale/04-schedule.sql`):** typed nullable `schedule` columns `slot_role` TEXT, `slot_flags` TEXT (CSV; empty tuple persists NULL), `stored_value_ct_kwh` (λ, rounded 0.1 ct - degeneracy rounding), `grid_value_ct_kwh` (π), `peak_pressure_eur_kw` (μ), `fallback_14a` BOOLEAN (run-level, repeated per row - the terminal_value pattern; TRUE = advisory no-§14a build). NULL everywhere = pre-feature/explain-off - consumers render exactly today's view, never a fabricated explanation. Served additively on `ScheduleSlotDto`/`SchedulePlanDto` (customer `GET /sites/{id}/schedule`) and on the admin diagnostics, where the persisted exact `stored_value_ct_kwh` replaces the approximation (`storedEnergyValueIsApproximation` is false only when EVERY rendered slot carries it).
- **Portal consumer - "a 'nothing to do' must name its true cause or stay silent" (2026-07-27).** The Fahrplan's idle sentence used to be a blanket fallback asserting "die Preisunterschiede lohnen kein Laden und Entladen" while inspecting NO price - which is what hid the flat-tariff freeze above for as long as it lasted (idle over a 20 ct spread, blaming the spread). `schedule.ts` `idleReason` now derives it from these persisted facts - dominant `slot_role` of the IDLE slots, `reserve_backup`/`reserve_peak` flags, `stored_value_ct_kwh` vs the window's best price - and returns **null when the optimizer recorded nothing**, in which case both consumers (`planInsightParts` on the Fahrplan chart, `planSentence` on the Anlagen-Seite mini preview) state the observation and claim NO cause. An idle stretch under a role the portal vocabulary does not know yet also makes no claim, so extending the role set can never invent copy. Pinned by `src/schedule.test.ts`.
- **Tests:** `tests/test_explain.py` (stationarity identities η·λ=π+wear / λ=η·(π−wear) within the ε-tie-break tolerance, Σμ=LP+ratchet exact, role vectors per scenario, fallback marking, plan-byte-identical on/off, explain-failure-never-sinks, constraint-inventory guard); `PortalApiTest`/`AdminApiTest` pin the read side + null degradation. The golden suite is the primary safety gate and stays untouched.
