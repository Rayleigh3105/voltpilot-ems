# Keyless data feeds: 15-min day-ahead prices + weather (portal widgets)

Ausgelagert aus `AGENTS.md` am 05.09.2026 (Abschnitt Nr. 74).


Two **KEYLESS** public collectors bring *real* data to the customer dashboard with **no captain secret**, plus tenant-scoped read endpoints and portal widgets. Run both via the compose `feeds` profile:

```bash
docker compose up -d                                                 # backbone + api
docker compose --profile feeds up -d --build market-data weather-collector forecast-collector
```

(The third `feeds` service, **`forecast-collector`**, is the shadow-mode forecasting heartbeat - see its own section.)

- **Day-ahead prices (15-min), energy-charts.info.** `services/market-data` gains a second `DayAheadPriceSource` - `EnergyChartsDayAheadPriceSource` (`energy_charts.py`) against `https://api.energy-charts.info/price?bzn=DE-LU` (Fraunhofer ISE, **no API key**). It is now the **default** source (`--source energy-charts`, env `MARKET_DATA_SOURCE`); ENTSO-E stays available as `--source entsoe` (still needs the token). Resolution is **derived from the data** (900 s spacing -> `PT15M`, 3600 s -> `PT60M`), so it follows the Oct-2025 EPEX shift to a 15-min MTU automatically. It reuses the existing `day_ahead_prices` hypertable + idempotent upsert (`source='energy-charts'`). The new `serve` CLI command refreshes **today+tomorrow on startup then every 6h** (`MARKET_DATA_REFRESH_SECONDS`) and is **coverage-aware** (`refresh.py`, captain-observed 2026-07-17: an unlucky 6-h phase missed the ~12:45 publication by hours and the Fahrplan ended at today's midnight): past `MARKET_DATA_PUBLICATION_HOUR` (Berlin decimal hours, default 12.75) with tomorrow's zone-scoped delivery day not fully covered it polls every `MARKET_DATA_FAST_REFRESH_SECONDS` (default 900) until coverage lands - bounded at local midnight (one loud WARN, never an all-night hammer), and an uncovered pre-threshold cycle caps its sleep AT the threshold so the unlucky phase can't rephase itself; the optimizer needs no change (15-min replans extend the horizon once prices exist). Details/tests: `services/market-data/README.md` + `tests/test_refresh.py`. `fetch` stays the one-shot/cron form. Prices are public per zone (no `tenant_id`, no RLS).
- **Weather forecast, Open-Meteo.** `services/forecast` gains `openmeteo.py` (keyless, EU-hosted `https://api.open-meteo.com/v1/forecast`, hourly `temperature_2m,cloud_cover,shortwave_radiation,direct_radiation,diffuse_radiation`) + `weather_repository.py` + the `weather_collect.py` collector (console script `voltpilot-weather`; `fetch` / `serve`). It reads every site's lat/lon and upserts into a new **`weather_forecast`** hypertable, keyed `(site_id, run_at, time)`. `OpenMeteoWeatherProvider` also adapts a fetched forecast into the PV model's `WeatherProvider` so the physical PV forecaster can consume **measured** irradiance instead of the clear-sky envelope (drop-in, no PV-model change). Weather carries `tenant_id` and is **RLS-scoped like telemetry**; the collector writes as the superuser (bypassing RLS) and stamps each row's tenant from the owning site.
- **Site geo.** `site.latitude`/`site.longitude` (WGS84) tie a site to its weather; the two dev sites are seeded (Berlin 52.52,13.405; Hamburg 53.5511,9.9937). Added by the api migration + the infra mirror; exposed on `SiteDto`.
- **Schema ownership.** The api migration **`V20260701010000__site_geo_and_data_feeds.sql`** (date-versioned so it never collides with api `V1/V2`, forecast `V3`, or market-data `V2026...`) is the canonical owner of the site columns + the read-side of both feed tables: it `CREATE ... IF NOT EXISTS`es `day_ahead_prices` **and** `weather_forecast`, grants the app role `SELECT` on both, and adds the `weather_forecast` RLS policy. This makes the api self-sufficient on a **fresh** DB (Testcontainers/staging) while layering cleanly over the dev bootstrap. Dev mirror: `infra/local/timescale/03-weather.sql` (site cols + `weather_forecast`, **no** RLS/grant - the `voltpilot_app` role doesn't exist at init time; the api migration adds them, exactly like telemetry).
- **API + portal.** `GET /api/v1/sites/{siteId}/prices` (zone series; site resolved via RLS -> 404 if foreign) and `GET /api/v1/sites/{siteId}/weather` (latest run; RLS-scoped) - both in `SiteController`, `openapi.yaml` updated. The portal adds a **day-ahead price bar chart** (15-min bars, colour-graded, today/tomorrow divider) and a **weather panel** (temperature/cloud/GHI) built on the design system + ECharts (`PriceChart.tsx`, `WeatherChart.tsx`, wired into `App.tsx`).
- **Marktpreise historical ranges.** The Marktpreise page (`pages/DataPages.tsx` `MarktpreisePage`) mirrors the **Historie** Tag/Woche/Monat/Jahr period pattern (shared helpers extracted to `src/periodNav.ts`, reused by both pages; same `.vp-seg`/`.vp-period-nav` markup). New endpoint `GET /api/v1/sites/{siteId}/price-history?range=day|week|month|year&at=<date>` (`SiteController.priceHistory` -> `PriceRepository.aggregate`/`summarize`, `PriceHistoryDto`) aggregates `day_ahead_prices` **in SQL via `time_bucket`** (15-min day / hourly week / **Europe/Berlin-daily** month+year - reuses `HistoryRange.window()`; a year is ~365 rows, not ~35k slots). Each bucket carries avg/min/max (the chart's band); the response also returns range summary stats (avg/min/max, cheapest & most-expensive slot ts, slot count, actual data coverage). The **day range on today extends `to` into tomorrow** so the forward-looking day-ahead curve stays visible (the page's core value, kept). `PriceHistoryChart.tsx` renders colour-graded bars with the "Morgen" divider for the day, and an average line + min/max band for week/month/year. Prices are market-wide per zone (no tenant), site-scoped via RLS (foreign site 404). **Data-reality:** the collector only fetches today+tomorrow (no backfill), so historical depth grows one day per collector day - the portal shows a designed empty state and a partial-coverage note ("erst Preise ab dem …") instead of a blank year. KPI values use a **regular** space before `ct/kWh` (not `NBSP`) so the unit wraps under the number in a narrow KPI card instead of being clipped at the tablet 3-across width (a real fix found in browser testing).
- **Tests (the assurance).** `services/market-data/tests/test_energy_charts.py` (parse/resolution-inference/window-clip/rejections + `fetch_and_store` into the in-memory repo, all offline via `FakeHttpClient`); `services/forecast/tests/test_openmeteo.py` (parse + PV-provider adaptation + collector store, offline); the api `PortalApiTest` gains `pricesEndpointReturnsZoneSeries` + `weatherIsTenantScoped` (real TimescaleDB+Keycloak: seed a row as superuser, assert the endpoint + tenant isolation), plus `priceHistoryAggregatesByRangeWithSummaryAndBandStats` + `priceHistoryDayExtendsIntoTomorrowForForwardLookingView` for the ranged endpoint (deterministic **far-past 2023 seed** so other tests' `now()` DE-LU rows never leak into the windows; note Berlin-day buckets serialize at the UTC day-start, so match aggregated days by value, not a `ts` prefix). Portal `npm run build` typechecks the new components. All keyless: no network in tests, no secret anywhere.
