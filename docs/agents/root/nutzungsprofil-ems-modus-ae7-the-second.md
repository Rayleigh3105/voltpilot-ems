# Nutzungsprofil / EMS-Modus (AE7): the SECOND adaptation axis (usage profile)

Ausgelagert aus `AGENTS.md` am 05.09.2026 (Abschnitt Nr. 57).


The usage profile (`arbitrage | peak | private`) steers the whole portal/edge **emphasis** (money-/peak-/flow-centric); contract **`docs/contracts/v2/usage-profile.md`** (spec `data/vp-ems-replatform/adaptive-ems-ui-v1-spec.md` §2/§3). **ONE truth, captain-decided: the profile is DERIVED, not a competing concept** — it generalises `site.plant_kind` + the module surface + the wizard Nutzung step; additive, a registry-/flow-less site is byte-identical v1.

- **Pure deriver + emphasis map, twinned + vector-pinned.** `deriveDefault`/`effectiveProfile`/`emphasisFor` live in Java `services/api …/profile/UsageProfileDeriver` and TS `frontend/portal/src/usageProfile.ts`, both asserting `docs/contracts/v2/usage-profile-vectors.json` (`UsageProfileDeriverTest` ↔ `usageProfile.test.ts`, the topology-vectors precedent — change rules on both sides + vectors together). **Rules (peak beats arbitrage beats private):** a peak strategy node (`vp.strategy.peakshaving`/`.atypical-grid`) OR `site.leistungspreis_eur_kw` → peak; a market node (`vp.strategy.market`) OR `plant_kind=direktvermarktung` → arbitrage; else private. A SETTABLE override (`arbitrage`|`peak` only — **`private` is derived-only, NOT settable since vp-nacht-bezug-e7 §3.3**; `isProfile` rejects it, `UsageProfileController` 400s it) wins over the derivation. Emphasis per profile = which of money/peak/flow/devices is prominent|secondary|minimal|hidden — the ONE contract AE2/AE3/AE4/AE6 **render** (never re-decide). Edge (Go, AE6) not built here; it consults the emphasis via the cloud later.
- **Signals + surface (cloud authority).** `UsageProfileService` gathers roles from the entity registry (catalog `category`/`controllable`) + the `vp.strategy.*` nodes in the site's **ACTIVE** flows (`FlowRepository.activeDocuments`) + plant_kind/Leistungspreis. `GET /api/v1/sites/{id}/profile` = effective+derived profile, override, emphasis, signals (RLS, foreign 404, admin switcher). `site.usage_profile_override` (migration `V20260719050000`, nullable enum, additive over V2 RLS) is echoed on `SiteDto` and set/cleared via `PUT /api/v1/sites/{id}/profile` (null clears → auto-derive). openapi tag `profile`.
- **Node governance (spec §3).** The flow catalog carries a static `gated` flag per node type (`FlowCatalog.isGated`/`gatedTypes`; both `catalog.json` copies synced, sync test enforces): **gated** = market-/grid-near (`vp.strategy.market` + the two contract-reserved `vp.strategy.peakshaving`/`vp.strategy.atypical-grid`, gated strategy nodes; peak-shaving's runtime path is now BUILT — see "Peak-shaving flow node (E5a)"; atypical-grid stays reserved for E5b); **free** = device control + all data/logic/action nodes (self-consumption is base behaviour, no longer a strategy node — report vp-nacht-bezug-e7 §3.3). Per-site enablement `flow_gated_node_enablement` (migration `V20260719060000`, RLS) via admin `GET/PUT /api/v1/admin/sites/{id}/flow-node-governance`. `FlowGovernance` (pure) is the rule; `AdminFlowController.activate` refuses a flow with a gated-not-enabled node (`gated_node_not_enabled`) **before** the compiler is contacted — placeable in a draft, activatable only after enablement. **Footgun:** the pilot market node IS gated, so `FlowApiTest` enables it before its OFF-flag `activation_disabled` assertion; a new flow with a gated node needs enablement to activate.
- **Auto-start (spec §3).** `FlowTemplates` maps profile→starter (market/peakshaving on the battery, pilot chain shape; **`private` has NO starter — self-consumption is base behaviour, not a strategy node, report vp-nacht-bezug-e7 §3.3, so auto-start skips `no_template`**) + `FlowTemplateService.autoStart` (idempotent seeding hook — reuses `FlowRepository.insertDraft` + `FlowClaims`; skipped `already_has_flow`/`no_battery`/`no_template`) via admin `POST /api/v1/admin/sites/{id}/flows/auto-start`.
- **Proofs:** pure `UsageProfileDeriverTest`/`FlowGovernanceTest`/`FlowTemplatesTest` (starter validates for all 3 profiles) + `usageProfile.test.ts`; Testcontainers `UsageProfileApiTest` (derivation, override set/clear, Leistungspreis→peak, governance GET/PUT, auto-start created+idempotent, RLS 404). **Boundary: no AE2/AE3/AE4 rendering, no AE6 edge diagram, no E3b customer editor** — only the profile model + emphasis contract + governance + templates they consume.
