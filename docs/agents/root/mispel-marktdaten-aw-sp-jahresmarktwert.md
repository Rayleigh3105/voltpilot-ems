# MiSpeL-Marktdaten: AW>0-Zeiten, SP¼, Jahresmarktwert (MP-7)

Die Rechengrundlage der Festlegung MiSpeL (BNetzA 01.10.2026) für Prämien-Viertelstunden und Marktprämie. Bauplan und Fundstellen: Konzept `vp-mispel-fundament`, § 8.5 (W3, W4).

- **AW>0-Zeiten = die Liste der ÜNB, nicht der Spotpreis.** Formel (24)¼ / (P12)¼ = `WENN[AW¼>0;1;0]` (A1 S. 38, A2 S. 31); welche Viertelstunden das sind, veröffentlichen die ÜNB unter „Negativer Spotmarktpreis – Übersichtstabellen“ (A1 S. 17 Fn. 8). Sammler `services/market-data/voltpilot_market_data/netztransparenz_aw.py` (keyless `CsvDownload.ashx?request=<base64>`), Tabelle `eeg_aw_zeit` (PK `regel, ts`, native Auflösung, keine Zeile = unbekannt). Sieben Regeln = die sieben Veröffentlichungen der Seite (`viertelstunde`, `viertelstunde_2ct` § 51b, `stunden_1..6`); welche für eine Anlage gilt, ist Stammdatum (MP-5). Zeitumstellung in den Tabellen: Frühjahr leere Zellen 02–03 Uhr, Herbst `Ja, Nein`-Paare (erst Sommer-, dann Winterzeit). Ein unveröffentlichter Monat liefert einen leeren Körper.
- **SP¼ = `day_ahead_prices` DE-LU**, keine eigene Tabelle (§ 3 Nr. 42a EEG). Lesen nur über `MispelMarktdatenRepository.spotmarktpreise` (PriceSlots-Lückenregel, ct/kWh, fehlend = `null`).
- **Jahresmarktwert** `annual_market_value` (PK `technology, year`; `solar`, `wind_an_land`, `wind_auf_see`, `allgemein`), Upsert „veröffentlicht schlägt vorläufig“ wie `monthly_market_value`. Quelle hat keinen Datendienst: gelesen wird die serverseitig gerenderte JW-Tabelle der Marktwertübersicht (nur das neueste Jahr; ältere nur per Postback).
- **Leser für Rechenwerk/Erlöse:** `services/api/.../repo/MispelMarktdatenRepository` — Liste gewinnt; ohne Liste Rückfall „AW¼ = 0 bei SP¼ < 0“ (`RUECKFALL_SPOT`) und der Zeitraum ist `vorlaeufig`; ohne beides `UNBEKANNT` (nie 0). Der Optimierer liest die Tabellen wie `monthly_market_value` direkt.
- **Schema-Spiegel (vier, synchron halten):** market-data `V20261002110000` (kanonisch), api `V20261002110000` (+ `GRANT SELECT`), `infra/local/timescale/07-mispel-marktdaten.sql`, `infra/prod/timescale/00-collector-tables.sql`. Abruf: `python -m voltpilot_market_data mispel-marktdaten [--monat YYYY-MM] [--persist]`; `serve --persist` einmal je UTC-Tag (laufender + zwei Vormonate).
- **Marktwertbasis aus dem Förderweg (MP-12, W3/W4):** an einem Berliner Tag in Abgrenzungs- oder Pauschaloption (späteste wirksame Fassung in `site_foerderweg`, ohne Fassung nie MiSpeL) rechnet die Marktprämie mit dem Jahresmarktwert Solar des Kalenderjahres und nur in AW>0-Viertelstunden; sonst unverändert Monatsmarktwert + „keine Prämie bei Spot < 0“. Drei Stellen, ein Regelwerk: Optimierer `voltpilot_optimization/marktwertbasis.py` + `pricing.marktpraemie_eur_mwh` (die Prämienreihe, die MP-10 für grün/gelb liest), Erlös-SQL `SlotEconomics.marktwertbasisJoinSql`/`PRAEMIEN_MARKTWERT_CT_SQL`/`praemienViertelstundeSql` (in `EarningsRepository.MARKET_VALUE_JOIN`), Fahrplan-Twin `SlotEconomics.Marktwertbasis` über `OptimizerDiagnosticsRepository.marktwertbasis`. Gleichlauf: `PortalApiTest.exportValueSqlMatchesTheSlotEconomicsCompositionVectors`; Prüfnachweis `MarktwertbasisErloeseTest`. **Regel-Eingang:** die AW-Differenzierung ist noch kein Stammdatum — SQL `SlotEconomics.AW_REGEL_SQL` = `NULL`, Python/Java `aw_regel=None`: die Liste trifft nie, W4-Rückfall, `SiteAggregate.marktpraemieVorlaeufig = true`. Das Folgepaket ersetzt genau diese Stellen durch die Spalte der Fassung. Fehlender Jahresmarktwert (laufendes Jahr, erscheint erst danach) = keine Prämie, nie der Monatswert. Der Vergleichswert `market_value_ct` der Anzeige bleibt Monatsdurchschnitt Solar (bis MP-18).
