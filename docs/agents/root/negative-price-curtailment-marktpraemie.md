# Negative-price curtailment + Marktprämie (fleet overview Phase 3)

Ausgelagert aus `AGENTS.md` am 05.09.2026 (Abschnitt Nr. 66).


Captain decisions #2/#3 (2026-07-06): the plan MAY curtail PV at negative prices, and a configured Marktprämie enters the realized-earnings math. One api migration **`V20260706040000`** carries both columns (`schedule.curtail_kw`, `site.marktpraemie_ct_kwh`).

- **Curtailment in the MILP:** `curtail_t in [0, pv_t]` joins the grid balance (`grid = load - pv + curtail + charge - discharge`), so a full battery at negative prices no longer FORCES a paid export. Deliberately NO price condition in the model - under symmetric spot pricing the economics curtail exactly when the price is negative (full curtailment then, since paid import beats own PV) and never at positive prices; details incl. the two epsilon tie-breaks in the "Optimization engine" section and `solver.py`'s docstring. Persisted per slot (`curtail_kw`), published as the OPTIONAL per-slot **`pv_limit_kw`** (= `pv - curtail`, an inverter feed-in CAP so a forecast overshoot is capped too; omitted when not curtailing, keeping non-curtailing payloads byte-identical) - an ADDITIVE schedule-contract extension, `schema_version` stays 1.0 (see Contracts).
- **Edge execution (dev edge + sim):** the SunSpec sim gains writable register 42 (`pv_limit`, uint16 0.01 kW, **0xFFFF sentinel = no limit**, power-on default; the model takes `min(diurnal PV, limit)` - a cap can only ever reduce). The Node-RED flow's slot selector passes `pv_limit_kw` through, the Guards clamp it to `>= 0` (SAFETY: never a negative limit, never a command to produce, battery caps untouched) and write FC6 addr 42 alongside the battery setpoint; **absent/invalid limit and the Default-Watchdog fallback write the 0xFFFF sentinel**, so a stale curtailment never outlives its schedule. The customer **edge-app ignores the field** (Go `plan.Parse` fixed struct) - real curtailment execution there is future work; its guards/fallback behavior is unchanged.
- **Marktprämie in earnings: SUPERSEDED (captain domain fix 2026-07-07).** The Phase-3 `site.marktpraemie_ct_kwh` (a manually entered FIXED ct/kWh premium) had the wrong semantics - fixed is the plant's ANZULEGENDER WERT, the premium is the dynamic monthly difference to the Monatsmarktwert Solar. See the section "Dynamic Marktprämie (anzulegender Wert x Monatsmarktwert Solar)" below; the old column is deprecated (kept one release, no reader/writer, `openapi.yaml` marks it), values were NOT migrated (different quantity). The both-sides crediting + simplified §51 suspension rule carried over unchanged.
- **Portal + tests for the premium moved with the dynamic model** - see "Dynamic Marktprämie" below. The curtailment tests (optimizer + contract) in the Optimization-engine bullet are unaffected.
