## Build & test

- **`npm run build`** = `tsc && vite build` (the type-check is the primary CI gate). **`npm test`** = `vitest run` (jsdom); `npm run test:watch` for the loop. Config in `vitest.config.ts` (separate from `vite.config.ts`); jest-dom matchers are wired in `src/test/setup.ts`.
- **Test files (`src/**/*.test.ts{,x}`) are EXCLUDED from the `tsc` build** (`tsconfig.json` `exclude`) so the production build stays decoupled from the test types; vitest type-checks them via its own esbuild transform. Prefer **pure, unit-tested logic modules** (e.g. `src/live.ts`) with thin render-only components - the pure module carries the exhaustive state coverage, the component test just asserts it renders. Component tests use `@testing-library/react`.

- **Interactive ink = one token: `--vp-action` (`#2C5282`, the brand navy `--vp-navy-2`, in `designsystem/tokens/colors.css`).**
  It is the single deep blue that passes WCAG AA both white-on-fill and text-on-white, used by the primary Button, links (`--vp-link`) and Stat/KPI ink fallback.
  The pale cornflower `--vp-primary` (#95B9FF) stays for DECORATIVE fills only (gradients, IconTiles, accent bars, tints) - contrast does not bind decoration.
  Retuning the brand action shade = change that ONE value; do not scatter new interactive blues.
- **Button/Card affordance is CSS, not inline JS.** `designsystem/components/core/core.css` owns `.vp-btn*` / `.vp-card*` with real `:hover` / `:active` / `:focus-visible`, so touch + keyboard get feedback (the old `onMouseEnter/Leave` handlers are gone). `core.css` is imported once in `src/main.tsx` after the tokens.
  Keyboard focus rings for non-Button chrome (nav, seg tabs, steppers, links, clickable rows) live in `src/index.css` via `--vp-focus-ring-color`.
- **Loading/empty/error states go through `src/components/States.tsx`** (`Skeleton`, `TextSkeleton`, `ChartCardSkeleton`, `TableSkeleton`, `ErrorState` with retry, `EmptyState`). Never ship bare `<p>Lade …</p>`; data pages show a shaped skeleton while loading and a distinct `ErrorState` (with a retry that bumps a `reloadKey`) on failure.
- **Dense table-row actions use `src/components/RowMenu.tsx`** (⋯ overflow popover; destructive items separated), not a row of side-by-side buttons. Its popover renders into `document.body` at fixed coords from the button's `getBoundingClientRect()` (viewport-clamped, flips up when no room below) - the same escape-the-clip pattern `InfoTip` uses. This is load-bearing: the host tables sit in `Card` with `overflow: hidden` (rounds the corners), so an `absolute` popover was clipped and the last/only row's actions (incl. destructive "Löschen") were unclickable. Any new in-card popover/menu must portal to body, not rely on `position: absolute`.
- Two non-existent token names silently fall back to hard-coded hex: use `--vp-border`/`--vp-primary` (NOT `--vp-color-border`/`--vp-color-primary`) and `--vp-radius-md` (NOT `--vp-radius-card`). Grep `--vp-color-`/`--vp-radius-card` before shipping.
- **ECharts surfaces read ONE shared palette via `src/chartTheme.ts` (`chartTheme()`), never hard-coded hex.** Canvas can't resolve `var()` at paint time, so `chartTheme()` reads the `--vp-chart-*` tokens (in `designsystem/tokens/colors.css`) from `:root` once (memoised) with token-value fallbacks. Call it INSIDE the render/`setOption` closure (needs `window`) and map `axis`/`ink`/`grid`/`axisLine`/`pv`/`temp`/`load`/`price`/`soc`/`charge`/`discharge`/`plan`/`cloud`. Re-theming the data surfaces = edit the tokens, not the charts. All charts (`TelemetryChart`/`ScheduleChart`/`PriceChart`/`HistoryChart`/`WeatherChart`/`PriceHistoryChart`/`ForecastQualityChart`) already do this.
- **Chart heights are responsive via CSS classes, not fixed inline px:** `.vp-chart` (`clamp(260px,40vw,340px)`), `.vp-chart.tall`, `.vp-chart.compact` (in `src/index.css`). A chart div just needs `className="vp-chart"` - no `style={{height}}`.
- **Every ECharts surface goes through the shared `useEChart(render, deps)` hook (`src/useEChart.ts`), never a hand-rolled init/resize/dispose.**
  It observes the CONTAINER with a ResizeObserver (not just window resize - sidebar collapse and grid reflow resize charts without a window event), calls `chart.resize()` and re-runs `render(chart, width)` at the new width.
  Use the `width` param for width-aware layout: every chart derives `narrow = width < 480` (Weather: 520) and then shortens axis names ("Leistung (kW)" -> "kW"), trims grid margins, or drops secondary y-axes.
  Conventions that keep phones clean, learned in real 375px browser testing: tooltips always set `confine: true` (never overflow the viewport, works for touch-tap tooltips); x-axis labels always set `hideOverlap: true`; do NOT use `alignMinLabel`/`alignMaxLabel` or padded label strings on CATEGORY axes - both degrade the auto-interval badly (charts collapse to 1-2 labels); for hourly week buckets on narrow widths, label only each day's FIRST bucket (weekday short, else `''`) with `interval: 0` + `axisTick: {show: false}` - the auto interval would repeat weekdays ("Mo Mo Di ...") and full "Mi 06:00" labels clip at the canvas edge (see `HistoryChart`/`PriceHistoryChart` `weekNarrow`).
- **Customer-facing jargon helpers in `src/format.ts`:** `ctPerKwh(eurMwh)` (÷10, the unit on a bill - customer surfaces speak ct/kWh, never MWh) and `zoneLabel(code)` (raw bidding-zone code -> "Deutschland"/"Österreich"/"Schweiz"; onboarding hides the code, the dashboard must not re-expose it). Gloss metric abbreviations (SoC, net power) inline with `InfoTip` in the `Stat`/`KpiCard` `label` (both accept a ReactNode). The Marktpreise analytics page deliberately KEEPS EUR/MWh as professional detail under a ct/kWh headline - do not strip it.
- **The Übersicht is ADAPTIVE (fleet mode from 2 sites).** `UebersichtPage` is a thin wrapper: multi-site customers get `FleetUebersicht` (money hero on `--vp-grad-hero` with count-up + 14-day spark, fleet status sentence, per-site cards from `GET /api/v1/overview`), single-site customers render the simplified `SingleSiteUebersicht`; a card click drills into the single-site body with "‹ Alle Standorte" back. ALL fleet wording/derivation is the pure, unit-tested `src/fleet.ts` (per-plant-kind wording - `site.plantKind` direktvermarktung "mehr verdient" vs. eigenverbrauch "gespart", mixed = neutral headline; `composeFleetSentence` goes amber and NAMES a silent device; `siteLiveFresh` requires an online device AND a fresh observation so replayed buffer data never renders as live); `components/FleetOverview.tsx` only renders. Fleet CSS block at the end of `src/index.css`; tiles reuse the `--vp-flow-*` channel hues. No Ø-Preis in fleet mode (captain decision).

The DEPTH lives on the linked pages: the Verlauf chart + verdict tiles + window toggle moved to the dedicated **Live-Daten page** (`pages/LiveDatenPage.tsx`, nav id `live`), the price mini-chart died in favour of the Marktpreise day view (`PriceChart.tsx` deleted), weather stats live on Wetter, the site quick-list on Standorte. Never re-crowd this screen; new detail belongs on (or behind) a detail page.
- **Charts must be self-explaining at a glance (captain: "it takes me a while to understand the diagrams").** Every data chart pairs its canvas with three plain-German pieces via `src/components/ChartExplain.tsx`: `ChartSubtitle` (one-line "was zeigt das?" under the title), `ChartLegend` (colour **swatch + plain label + unit** per series - NO field names, NO raw echarts legend; pass the resolved `chartTheme()` hex so the swatch matches the canvas; optional `onToggle`/`hidden` turns rows into series-toggle pills), and `ChartInsight` (the takeaway in ONE sentence - "die Aussage"). Styles live in `src/index.css` under "Self-explaining chart chrome" (`.vp-chart-sub`/`.vp-chart-legend`/`.vp-swatch-*`/`.vp-insight`). The built-in echarts `legend` is deliberately REMOVED from `ScheduleChart`/`HistoryChart` - the HTML legend replaces it (frees vertical space, wraps cleanly on phones, speaks units). The legend+insight live INSIDE the chart component so they travel with it; gate the page's `ChartSubtitle` on data-present (don't describe a chart that isn't there in the empty/error state).
- **Time-axis charts show a "Jetzt"-marker + shaded past.** On the category-time charts (Fahrplan `ScheduleChart`, Historie day `HistoryDayChart` + energy day view, Wetter `WeatherChart`), a solid `t.price` `markLine` at the slot nearest `Date.now()` labels "Jetzt" and a `markArea` from index 0→now shades the elapsed part (`itemStyle {color: t.axis, opacity: 0.08}` - subtle but visible on white). Fahrplan also keeps the dashed "Morgen" divider. On an HOURLY category axis the markLine label renders rotated along the line - pin it with `rotate: 0` (WeatherChart does; same family as the TelemetryChart edge-label gotcha).
- **Weather times are UTC in the API, local in the UI - and the hero picks the NEXT hour (`src/weather.ts`).** `GET /sites/{id}/weather` returns the latest collector run's FULL hourly series as UTC ISO (`...Z`) timestamps starting at 00:00 UTC of the run day, i.e. the array BEGINS with past hours. Real prod bug (2026-07-06): the Wetter hero rendered `points[0]` as "Temperatur (nächste Stunde)" (a value up to ~24h stale) and the default axis-trigger tooltip header showed the raw UTC ISO string, which reads as "23 Uhr" while actually being 01:00 Berlin - together "the temperatures do not match". The stored data itself is CORRECT UTC (openmeteo.py requests `timezone=UTC`; verified hour-by-hour against Open-Meteo's Berlin-local series, pinned by `test_hourly_times_are_utc_never_local`). All selection/labeling goes through the pure `src/weather.ts` (`nextHourIndex`, `nowMarkerIndex` for the Jetzt marker, `hoursAhead` for the honest Vorhersagehorizont, `tooltipHeader`/`axisHourLabel` in German local time) - unit-tested in `weather.test.ts` with the exact captain scenario; new weather-like surfaces must reuse it, never render a raw `ts` string.
- **Customer-facing price axis is ct/kWh, not EUR/MWh.** Fahrplan + Historie day + the Übersicht price mini-chart divide `priceEurMwh` by 10 and label the axis "ct/kWh" (the unit on the bill). Only the Marktpreise analytics page keeps EUR/MWh as professional detail under a ct/kWh headline (see the format.ts bullet).
- **The Live-Daten page is a status-first hero, not a chart (report direction B).** The page's card body (`pages/LiveDatenPage.tsx`) is `components/LiveHero.tsx`: (1) one German **status sentence** ("Ihre Anlage erzeugt gerade X kW. Die Batterie lädt (76 %). Y kW fließen ins Netz."), (2) four **verdict tiles** (Solar/Batterie/Haus/Netz - value + state word, battery with a SoC bar + Lädt/Entlädt + derived kW, the Netz label flips Netzbezug/Einspeisung), (3) the animated **energy-flow diagram** (`components/EnergyFlow.tsx`), then (4) the **Verlauf** chart below (the existing `TelemetryChart`). This mirrors the edge device's `:8484` dashboard so the customer sees the same picture at home and in the portal. ALL derivation is in the **pure, unit-tested `src/live.ts`** (`buildSnapshot`, `deriveBatteryKw`, `pvState`/`loadState`/`batteryState`/`gridState`, `flowState`, `composeStatusSentence`); the components only render it. Every threshold + wording is lifted from the edge `dashboard.js` `renderKpis`/`renderFlow` (0.05 kW deadband, `DEADBAND_KW`). Signs NEVER reach the customer (labels flip + `Math.abs`).
  - **Battery power is derived, never a telemetry field:** `battery = powerKw - loadKw + pvPowerKw` (`deriveBatteryKw`), the same power-balance convention as the edge `internal/history` and the Historie rollups. **Absent input → absent (null), never 0** - an unknown flow must not read as "idle". `buildSnapshot` derives it PER sample then takes the newest derivable one; SoC is the newest PLAUSIBLE reading (`sanitizeSoc`).
  - **Energy-flow diagram** is a dependency-free React SVG port of the edge `buildFlow`: 4 nodes (PV top, Batterie left, Haus right, Netz bottom) around a hub, animated dashed spokes whose direction encodes charge/discharge + import/export (`flowState`). It has WIDE (desktop diamond) and NARROW (phone portrait cross) layouts picked from the container width via a ResizeObserver. The 4-hue palette is the `--vp-flow-*` tokens in `index.css` (lifted from the edge `dashboard.css`: PV orange, Haus purple, Netz teal, Batterie green) - referenced via CSS `var()` straight in the SVG (SVG can resolve `var()`, unlike canvas), so re-theming is a token edit. `@keyframes vp-flow` drives the dash offset; honors `prefers-reduced-motion`.
  - **Verlauf window toggle (`1 Std / 3 Std / Heute`)** fetches ONLY the selected window (`api.telemetry(id, from, to)`, `windowStart()` in `LiveDatenPage`) so >3h windows come back downsampled (F6). `TelemetryChart` takes a `windowLabel` prop for its subtitle/insight copy. On the dedicated page the chart is always visible (the old phone collapse toggle existed only because the chart shared the Übersicht).
  - **Freshness (unchanged from before):** green "Stand vor X" inside the 5-min `ONLINE_WINDOW_MS` (`api.ts`), grey "keine aktuellen Daten" beyond it; when stale the hero keeps its last-good values but the status sentence goes honest-grey (`composeStatusSentence(_, false)`) and the tiles + flow dim (`.vp-stale`). Background poll failures stay SILENT.
- **Telemetry endpoint is server-side downsampled:** windows > 3h come back as 1-minute `time_bucket` averages, point `ts` = bucket START, and when the row cap bites the OLDEST points drop, never the newest (`TelemetryRepository`). Consequences for the portal: the "newest point" can read up to ~1 min old even with 10 s live data (the freshness chip understates, never overstates), and the F6 regression test `PortalApiTest.telemetryWindowStaysCompleteAndCurrentWhenRawCountExceedsTheLimit` pins the complete-and-current window.
- **TelemetryChart uses a TRUE `type: 'time'` x-axis** (data as `[ms, value]` pairs) - a category axis gives every sample equal width and massively distorts time under mixed sampling rates (15-min seed next to 10-s live ingest was the real symptom). New telemetry-like charts must do the same. **Jetzt-marker-at-the-edge gotcha:** on a LIVE chart "Jetzt" is always the right edge, where an inside-positioned markLine label renders ROTATED along the line - pin it with `rotate: 0, align: 'right'` (the Fahrplan/Historie charts never hit this because they skip the marker on the last bucket).
- **Exactly-four stat tiles use `.vp-grid-stats-4`** (explicit 2x2, 4x1 at >=1200px) so the 4th tile never wraps alone and phones never stack one-per-row; the `auto-fit` `.vp-grid-stats` stays for grids with other tile counts (Historie has 6).
- **Site location is a map with a draggable pin, not raw coordinate fields (`components/LocationMap.tsx` + pure `components/geo.ts`).** ONE shared, controlled component for all three site forms - `CreateSiteDrawer` (customer + admin), `StandortePage` `SiteEditForm`, and `Onboarding` `SiteStep`. Parents hold coordinates as `number | null` and pass `{lat, lon, onChange}`; the component owns the Leaflet map (keyless OpenStreetMap tiles, `leaflet` npm dep - **portal only, never the edge app**), the readable coord line (via `fmtCoords`), and an expert "Koordinaten manuell bearbeiten" expander whose two fields stay in sync with the pin. No pin yet -> a DACH-level view (`geo.DACH_CENTER/ZOOM`) invites click-to-place; a pin -> a brand-navy DivIcon marker the user drags (`draggable:true`); the onboarding `LocationSearch` result just sets `lat/lon` and the map flies there (`PIN_ZOOM`) for fine-dragging. The pin is a CSS/SVG **DivIcon** on purpose - Leaflet's default PNG marker icons break under the bundler. `scrollWheelZoom:false` so the page still scrolls over the map; one-finger touch pans/drags (standard Leaflet handling); `.vp-map` sets `position:relative; z-index:0` to CONTAIN Leaflet's internal high z-indexes (zoom controls ~1000) inside the map box so they never float over a Drawer/other cards.
  - **Pin<->field sync has no suppression flag** (an earlier `fromManual` ref got STUCK true when a manual edit resolved to the current value = a no-op `onChange` that React bails on, so the effect never ran to clear it, and the NEXT external change was swallowed). Instead the sync effect rewrites a field only when `fieldMatches(text, prop)` is false - so the text the user is actively typing (incl. a German `52,52` comma) is never reformatted under the cursor, and every external change (drag/search/clear) still syncs. Regression pinned by `LocationMap.test.tsx` "still reflects an external change after a manual edit that resolved to the same coordinate".
  - **Pin drags respond only to TRUSTED pointer events.** Leaflet's Draggable uses pointer capture, so synthetic `dispatchEvent(new MouseEvent/TouchEvent)` do NOT move the marker - a real CDP drag (`chrome-devtools-axi drag @from @to`, which Chrome routes through the same unified pointer path for mouse AND touch) does. Verify pin dragging with the native drag, not JS-dispatched events. Logic tests live in the pure `geo.ts` (`syncFromFields`/`parseCoordInput`/`isValidLat`/`isValidLon`); the component test mocks `leaflet` (needs real layout jsdom lacks).
