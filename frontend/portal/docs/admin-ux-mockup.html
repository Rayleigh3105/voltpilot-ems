Design-Review · Portal-Admin

Portal-Admin ("Plattform") — vorher / nachher

Statische Darstellung in der echten VoltPilot-Optik (echte Design-Tokens). Zeigt die umgesetzten, design-system-treuen Verbesserungen an den vier Plattform-Seiten und — klar als Vorschlag markiert — den größeren, nicht umgesetzten Wurf: eine echte Plattform-Übersicht. Die Umsetzung ändert nur Darstellung/Struktur, keine Logik/API/Routen.

Mandanten — die de-facto Admin-Startseite

Vorher springt der Admin direkt in eine nackte Tabelle: kein Gefühl für die Größe der Plattform, dünner Kopf, ID-Spalte frisst Scan-Fläche, grauer „nichts vorhanden“-Satz. Nachher: iconisierter Kopf, ein ruhiger Pulse-Streifen (aus den vorhandenen Mandanten abgeleitet — kein neuer API-Call), gestraffte Tabelle und ein gestalteter Leerzustand.

Leerzustände & der Mandanten-Umschalter

Der Leerzustand nutzt jetzt das vorhandene Design-System-Muster (IconTile + Titel + Text + CTA) statt eines grauen Satzes. Der Umschalter — das wichtigste Werkzeug des Admins — bekommt ein Gebäude-Icon und einen Caret, damit er unverkennbar das Mandanten-Steuerelement (und ein Dropdown) ist.

Vorschlag — nicht umgesetzt Eine echte Plattform-Übersicht

Der eigentliche Fix für „kein Puls auf einen Blick“: eine eigene Landing-Seite für den Plattform-Betreiber mit echten mandantenübergreifenden Kennzahlen. Braucht einen neuen Aggregat-Endpoint und einen Nav-Eintrag — also außerhalb von „keine Logik-/Routen-Änderung“. Deshalb hier als Mockup, damit der Captain entscheidet. Der oben gezeigte Mandanten-Pulse-Streifen ist die ehrliche, heute lieferbare Teillösung.

Umgesetzt vs. vorgeschlagen

jetzt geliefert

  • AdminPageHead auf allen 4 Seiten — eine Konsole
  • EmptyState überall (statt grauer Sätze)
  • Umschalter mit Icon + Caret + Focus-Ring
  • Mandanten-Pulse (Segment-Split, ohne neuen API-Call)
  • Straffere Tabelle (Name+ID gestapelt, Chevron-Drill-in)
  • Konsistente destruktive Aktion (Papierkorb-Icon)

Captain entscheidet

  • Plattform-Übersicht als eigene Landing (neuer Endpoint + Route)
  • Suche / Filter / Sortierung auf den Tabellen
  • Sammelaktionen (Multi-Select provisionieren / (de)aktivieren)
  • Ein gemeinsamer Mandanten-Picker (die 2 Extra-Selects entfallen)
  • Health-Spalte pro Mandant (Geräte online/gesamt, zuletzt gesehen)
